# 地图分享现行约束

合同：`UPLOAD_CONFIRMATION_MAP_SHARING_V2`。2026-10-03，Founder最终澄清；作为memory-bank/design-document.md的现行摘要。所有后续任务、代码生成、验收与部署必须遵守。旧候选包、旧日志、V1网页演示不得恢复旧产品流程。

## 条例覆盖本人已上传记录（当前）

补充合同UPLOADED_V1_ACCOUNT_CONSENT_V1。服务器完成态“已上传”的V1记录，其原上传已表示分享确认；当前条例明确确认本人此前及以后已上传的记录可按规则转换到V2，用于地图展示，并确认有权分享这些安全信息。缺少旧版逐条技术字段不再拦截合格已上传记录，不需要原设备再次补交才能转换。真正的本人当前v3接受是统一覆盖的依据；旧v2范围不自动升级为新同意。

服务器按准确finalized direct / exact APPROVED draw判定已上传，不能只凭客户端标签或“在observationCandidates表里”判定；private_saved、pending、失败、删除/注销保持私有或不可用。原上传溯源字段与设备送达队列仍可保存，但不是正常历史准入门。新条例的明确全部已上传范围取代旧逐条选择模型；不能靠旧权限行或缺技术字段要求用户再次选择。位置、安全、有效性和删除门在准入前保留，V2正式数据及投影同事务自动生成。

同意时持久扫描本人来源，只唤醒服务器已完成且满足当前准入条件的记录。2026-10-04用户明确恢复生产桥接后，当前真实合格批次及全局continuous已执行/验证；旧暂停门不再是当前断点。Agent不替真实用户接受新条例，一人的同意不覆盖其他账号。

后端只有一套全局bridge与每分钟timer，不为账号单独配置。本人接受当前条例自动触发本人历史扫描；之后成功上传、更新与删除由原V1事务写持久事件自动传播。当前证据以progress顶部为准；旧3条direct分别属于未接受v3的其他账号，不得为凑批次改所属或伪造同意。仅上传默认显示筛选关闭属于既有地图展示行为，不构成第二次授权。

旧v2时期“历史不自动授权”“仅已有逐条意图才扫描”“既有DO_NOT_SHARE不得覆盖”已被本合同取代，不作为v3准入依据。冻结包仅保留追溯。

## 公开资料接点（当前）

2026-10-04地图资料接点：生产已绑定当前本人安全昵称、独立公开头像副本、真实核验备注及首次上传时间。旧direct备注仅在本人当前条例已接受后由客户端自动后台补审，使用当次临时OpenID并只存exact-hash安全证明；没有新授权或分享按钮。V2详情只读公开投影，Freshness仍用observedAt。正常active账号举报、封禁/异常/受限制不计数，10个不同合格用户隐藏。最新证据与状态见progress顶部及docs/delivery/v2-e-task-22-map-display-and-public-metadata-audit.md。

## 直接上传备注审核及失败重试（当前）

直接上传的新记录必须先取得真实微信security.msgSecCheck明确pass，才创建完成态V1记录；不通过、待复核或API异常不能以本机“已上传”掩盖失败。未通过保留本机待上传快照、备注及首次位置，在“我上传的版面”复用修改备注弹窗恢复原job上传，不重新识别、增加双位置核验或再次要求分享。修改成功后只显示V1“已上传”，并继续由本人当前条例与全局bridge处理V2准入。失败重启不会自动重复提交同一拒绝备注。该规则与旧已上传direct备注后台安全补审并存，不要求历史记录重新上传或二次分享。实现与证据见docs/delivery/v2-e-task-22-direct-upload-note-review-and-retry.md。

## 唯一正常分享路径

1. 辅助抽赏：决定收手→原分享弹窗→愿意并拍摄赏票→原上传确认及核验。
2. 直接上传版面：原确认并上传版面→版面确认及备注安全检查；没有赏票／双位置比较任务。
3. 两条路径原上传确认表达本条分享意愿及有权分享，核验完成后数据留在V1。是否同意条例、V2是否可用，均不阻止V1正常上传。
4. 当前账号同意条例后，合格V1来源通过bridge准入V2；审核/授权在本地→V1、V1→V2门禁完成。V2已准入正式来源自动生成地图投影和Marker，不设二次审批、授权或发布操作。地图不能直接读取V1形成Marker。
5. 本人记录仅显示V1“已上传”，不要求V2授权或公开回执，不显示单独的已公开状态。成功弹窗只留回首页，明确已上传及同意条例后自动转化到地图。

禁止重新加入“地图分享选择”“我确认有权分享，并分享至地图”、map-source-choice或等价逐记录二次发布界面。SHARE／rights／follow-current-version在服务端存在，由原上传确认取得；账号条例同意与位置／安全／有效性等公开门保留。

## V2准入即自动地图

合同补充：`V2_ADMISSION_AUTO_MAP_V1`。SOURCE/RESOLVE/PROJECT属于V1→V2准入预计算；合格正式V2来源、关联、贡献与地图投影在一个事务落库。审核/权限/关联尚未满足的输入留在V1或私有bridge工作队列，不先写正式V2数据再等待审批。已准入数据后续的删除、注销、过期、更新与安全撤除自动传播，不追加用户授权。控制/任务/工作队列表不代表正式V2地图来源。

## V1 持久化与 V2 授权

V1 observationCandidates.uploadSharingAuthorization随原确认在同一事务写入；可信时间、所属账号、未删除状态和披露版本由服务端检查。客户端提交当前披露版本与rights确认，不把条例接受状态写成客户端事实。辅助抽赏核验可继续进行，V1的本条意图不能等待核验或V2授权表后才保存。

当前v3条例真实接受，统一覆盖该账号此前及以后完成上传的记录，构成有权分享这些安全信息的确认。V2 bridge从服务器完成态和当前账号scope派生SHARE/rights/follow-current权限，在原子准入事务中写入V2权限与正式数据。历史V1无需存在旧uploadSharingAuthorization字段，也无需原设备补送；旧逐条DO_NOT_SHARE模型由明确涵盖全部已上传记录的新条例同意取代。未完成上传、核验失败、删除或注销不得因此恢复或公开。

设备上的旧意图队列保留为原上传溯源/兼容送达重试，不再决定历史已上传来源能否转换。队列每批最多20条、公平轮转并处理并发触发，不因前面的核验未通过记录阻塞。没有当前真实v3条例同意时保持V1，不把旧v2同意自动升级为新授权。

当前条例ACCEPT与CONSENT_EVENT同事务登记。后台以持久游标有界扫描本人全部V1记录，通过准确finalized direct / exact APPROVED draw及当前准入条件筛选；未核验/私有保存会跳过但不阻塞后续已上传记录。V1迟到意图的UPLOAD_INTENT仍保留幂等唤醒能力。生产暂停时私有工作等待恢复，2026-10-04当前已获恢复授权并运行，不重新要求逐账号桥接审批。旧manage-map-player-source及ownerEntryEnabled保持关闭，不作为正常分享或兼容选择入口。
