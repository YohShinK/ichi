# V1 Board Outlook Algorithm

> 状态：V1-D 工作规格，待用户验收
>
> 算法版本：`board-outlook-v1.1.0`
>
> 更新时间：2026-08-08

## 1. 目的与边界

“局面可能性”是根据用户已经核对的当前版面，展示几个在固定观察窗口内可能发生的具体事件。它替代工作台中只按用户目标展示“一抽、二抽、三抽”命中率的做法，但不替代计算内核中的四种方案比较或用户硬约束方案。

它是概率事实，不是抽选建议。算法不根据累计花费、用户画像、市场价、历史输赢或任何外部信息挑选事件，也不提供“立即抽取”、排序、评分、默认门槛或推荐文案。

只有在对应事件概率严格等于 `100%` 时，界面才可以使用“必定”；其余情况只能使用“概率为”或“可能出现”，不得用“肯定会有”。每次确认或撤销一抽后，必须根据最新版面重新计算，不能把本轮结果当成下一轮保证。

## 2. 固定输入

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| `remainingTickets` (`R`) | 当前普通奖券余票总数 | 已核对的本机版面快照 |
| `largeTickets` (`L`) | 当前仍可抽到的大赏券数 | 每级余票与本地大赏分类求和 |
| `smallTickets` (`S`) | 当前仍可抽到的小赏券数 | 每级余票与本地小赏分类求和 |
| `targetTickets` (`T`) | 当前仍可抽到的已选目标券数 | 已选目标与每级余票求和；未选目标时缺省 |
| `windowDraws` (`k`) | 固定观察窗口 | `min(3, R)` |
| `unitPriceMinor` | 单抽最小货币单位金额 | 只用于显示窗口累计成本 |

大赏、中赏和小赏的定义不在本算法重复判断：大赏为 A—F 中总票位 `≤ 5` 的奖级；中赏为 A—F 中总票位 `6—9` 的奖级；小赏为 A—F 中总票位 `≥ 10` 的奖级，以及 G—Z／`OTHER`。分类仍由 `packages/board-layout` 的本地规则从已核对总票位派生。

`R ≤ 0`、任一计数非整数／为负、或 `L`、`S`、`T` 大于 `R` 时，结果为不可计算，不渲染任何事件概率。

## 3. 概率规则

所有事件都使用不放回超几何分布。对于类别中有 `M` 张券的事件，恰好抽到 `x` 张的概率为：

```text
P(X = x) = C(M, x) * C(R - M, k - x) / C(R, k)
```

算法保存约分后的精确分数；网页只在最后一步按既有规则格式化为小数点后三位百分比。窗口累计成本为 `k × unitPriceMinor`，只是“若记录这 k 抽时的累计成本”，不能写成建议投入金额。

## 4. 固定事件目录

事件按下面的稳定 ID 输出，不做分数、吸引力或推荐排序。用户选择目标时，目标事件只增加一条事实，不得让其取代其他版面事件。

| Event ID | 出现条件 | 概率 | 界面表达 |
| --- | --- | --- | --- |
| `TARGET_HIT_WITHIN_WINDOW` | `T > 0` | `P(X ≥ 1; M=T)` | `3 抽内至少一张目标` |
| `LARGE_PRIZE_WITHIN_WINDOW` | `L > 0` | `P(X ≥ 1; M=L)` | `3 抽内至少一张大赏` |
| `NON_SMALL_WITHIN_WINDOW` | `0 < R-S < R` | `P(X ≥ 1; M=R-S)` | `3 抽内至少一张非小赏` |
| `NO_SMALL_WITHIN_WINDOW` | `S = 0` | `P(X = 0; M=S)` | `3 抽内全非小赏` |
| `TWO_OR_MORE_SMALL_WITHIN_WINDOW` | `S ≥ 2` 且 `k ≥ 2` | `P(X ≥ 2; M=S)` | `3 抽内两张或以上小赏` |

当 `R < 3` 时，所有“3 抽”改写为“剩余 `R` 抽”。当同一事件达到 `100%`，可将“概率为 100.000%”写为“必定发生”；当事件不满足出现条件时不伪造 0% 卡片。窗口观察使用固定顺序：目标、大赏、非小／全非小、两张或以上小赏，不允许按概率高低把某个结果标成“最值得”。

## 5. 固定案例

给定 `R=20`、`L=2`、`S=8`、`T=1`、`k=3`：

| 事件 | 精确结果 | 展示值 |
| --- | --- | --- |
| 目标至少一张 | `3 / 20` | `15.000%` |
| 大赏至少一张 | `27 / 95` | `28.421%` |
| 非小赏至少一张 | `271 / 285` | `95.088%` |
| 小赏两张或以上 | `98 / 285` | `34.386%` |

后续实现必须把这些案例及空票池、无大赏、全非小赏、余票少于三张、类别边界和撤销后重算写入机器可读向量。任何公式、事件目录、窗口规则或文案语义的变更都必须创建新的算法版本，不得静默改写 `board-outlook-v1.1.0` 的输出。

## 6. 代码与界面接入

实现时创建平台无关的 `packages/core/src/board-outlook.ts` 和对应单元测试；其输入只接受已汇总的 `R/L/S/T/k`，不依赖 React、网页文案或版面标签。网页适配层负责调用 `derivePrizeClassification`、汇总各类别剩余券数、选择显示文本，并将核心结果渲染为“局面可能性”抽屉。

该抽屉必须固定显示“结果不保证；停止仍可选”，不显示执行抽取按钮。它可以显示本观察窗口的累计成本，但不可把成本和任何事件写成应该继续抽取的理由。
