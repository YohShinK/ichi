# V1 版面识别目标与大中小赏呈现

> 状态：APPROVED
>
> 更新时间：2026-08-07

## 1. 固定提问边界

每次导入一张版面照片时，识别服务只要求模型按 `recognition-contract` 输出可核对的结构化事实、置信度、问题原因与人工动作。模型不得设计组件、输出 HTML/CSS、猜测被遮挡信息，也不得判断某个奖级是不是大赏、中赏或小赏。

固定提问应要求模型：“从整张一番赏兑换进度版中提取下表字段；看不清、遮挡或无法确认的字段必须标为未知并给出置信度，不得猜测。”

| 识别项目 | 模型输出 | 后续用途 |
| --- | --- | --- |
| 版面完整度 | 完整／缺边／不确定，全部普通奖级是否可见 | 决定是否可建立票池或要求重拍 |
| 奖级集合 | 每个普通奖级的标准标签、原始标签、奖品名称（如有） | 决定页面显示哪些奖级 |
| 每级总票位 | `totalSlots` | 用户看到该赏一共可抽几次；本地判断大／中／小赏 |
| 每级已贴票位 | `coveredSlots` | 用户核对已被抽掉几张；版面显示实心票位 |
| 每级空票位 | `openSlots` | 求当前余票与每级概率 |
| 每级未知票位 | `unknownSlots` | 阻止不可靠的总数和概率计算 |
| 票位排布 | 方向、行数、列数、二维位置 | 还原票位换行和版面阅读顺序 |
| 单抽价格 | 金额、币种、原文、置信度、手写／缺失状态 | 计算累计花费与包套成本 |
| Last 与辅助区块 | Last、Double Chance、标题、说明等的内容和位置 | 单独显示；不计入普通抽数 |
| 问题与置信度 | 低置信、缺边、计数矛盾、未知区块及人工动作 | 进入统一“无法建立票池”或局部核对 |

票池总数、当前余票、已抽总数不由模型自由猜测，而是分别由可靠奖级的 `totalSlots`、`openSlots`、`coveredSlots` 在本地求和；守恒不成立时必须要求用户核对。

## 2. 大中小赏派生规则

大赏／中赏／小赏是本地展示分类，不是识别模型字段：

| 条件 | 呈现类型 |
| --- | --- |
| 标签为 A—F，且 `totalSlots ≤ 5` | 大赏 |
| 标签为 A—F，且 `6 ≤ totalSlots ≤ 9` | 中赏 |
| 标签为 A—F，且 `totalSlots ≥ 10` | 小赏 |
| 标签为 G—Z 或 `OTHER` | 小赏 |
| `totalSlots` 未知、矛盾或无法确认 | 不建立正式票池；先进入核对，不派生展示类型 |

因此，同一页面可同时出现任意数量的 A—F 大赏：A／B／C 可以都是大赏，下一张版面中的 A／B／C／D 也可以都是大赏。F 以下即使票数很少，仍统一使用小赏呈现。三档分类互斥。

### 2.1 本地算法

`packages/board-layout` 提供唯一实现 `derivePrizeClassification({ label, totalSlots })`：先把标签去除空格并转为大写，再检查 `totalSlots` 是否为正整数。无效票数返回未确认，调用方必须停在核对流程；有效输入返回呈现类型 `large`／`medium`／`small`。`derivePrizePresentation` 是只取呈现类型的兼容入口。两者不读取图片、不访问网络，也不根据奖品名称、市场价值或用户目标改变分类。

## 3. 版面呈现规则

| 呈现类型 | 奖级图标 | 票位 | 网格占位 |
| --- | --- | --- |
| 大赏 | 更大 | 更大票位；最多 5 格一排 | 每行 2 个正方形区块；第 3 个起进入下一行 |
| 中赏 | 紧凑 | 票位从左到右排成票条；空间不足时才续到下一行 | 每级独占一整行的横向区块，排在大赏下方 |
| 小赏 | 紧凑 | 票位从左到右排成票条；空间不足时才续到下一行 | 每级独占一整行的横向区块，排在中赏下方 |

无论大中小赏，已贴票位都使用实心格，空票位使用空心格；概率、撕开、累计花费、撤销和抽取记录的行为保持一致。
