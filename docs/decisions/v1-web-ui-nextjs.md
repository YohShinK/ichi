# V1 UI Next.js 网页交付决策

> 状态：APPROVED
>
> 日期：2026-08-08；2026-08-11 修订

## 决策

V1-26 最初使用 Next.js 手机优先网页建立低保真页面流；经 V1-29 完整设计、实现和用户验收后，Next.js 网页现为小程序全部页面、内容、组件、视觉、动效与交互的完整批准基线。微信小程序仍是最终产品运行端，但后续工作不是重新设计或在旧小程序壳上继续编写 UI，而是把整套网页一比一照搬为 WXML/WXSS、TypeScript 和微信平台能力。只允许 HTML/CSS/JavaScript 到小程序语法，以及浏览器 API 到微信 API 的必要平台适配。Figma 可以作为可选设计参考，image2 只负责视觉探索和非交互素材，不承担实施门禁。

## 边界

- 领域计算、会话状态机、版面 schema、识别契约和 Storage 核心包保持平台无关；
- `apps/web/` 承载 V1 已验收的完整页面设计与运行行为；浏览器能力按后续区块通过适配层映射；
- `apps/client/miniprogram/` 是最终客户端工程基座；当前只保留 V1-C Storage 和平台验证入口，后续一比一承载网页验收后的全部正式产品页面；旧壳不是视觉或页面设计基线；
- UI 不下发远程可执行代码；识别仍只返回结构化数据，网页按随包注册表渲染；
- V1-D 已交付并验收完整网页、组件和基础规则；V1-E/F 负责一比一照搬为小程序、接入微信能力并验证发布质量，不得重新设计、重排、简化或替换已验收 UI。
- image2 作为视觉设计环节：接收已确认的 HTML 布局作为结构参考，生成视觉探索或非交互素材；最终必须回到真实 React/HTML/CSS 组件，不能把生成图当作交互 UI。

## 影响

V1 的 UI 工作流现为“Next.js 完整批准基线 + 微信小程序一比一照搬交付”。V1-D 的全部页面、行为、视觉、组件、动效和基础算法已经用网页、浏览器和 Playwright 验证；V1-E/F 将按整页结构与设计参数照搬为 WXML/WXSS、接入微信平台能力并完成开发者工具／真机验证。Next.js 是设计与行为事实源，微信小程序是最终运行端；两者不是两套可独立发挥的 UI。隐私、计算边界、会话语义、区块顺序和核心数据架构不变。
