# V2 Contribution Verification Lifecycle

> 状态：V1-D 工作规格，待用户验收
>
> 版本：`contribution-verification-v1.0.0`
>
> 更新时间：2026-08-08

## 1. 决策

用户的“收手”流程在提交赏票照片后结束，不再向用户展示“核对结果”或“待发布预览”两个独立页面。用户只负责：同意分享、拍摄完整赏票、填写地点与备注、提交核对。赏票计数、与本机记录的比对、当前版面状态计算、私有保存和地图发布由服务端处理。

采用纯后台核对路径：用户点击提交后立即结束拍摄流程，但仍留在一番赏版面，以中央状态框显示“已提交／后台正在核对本次提交”。每张确认导入的版面在创建时获得 `boardId`；用户点“继续”后再次抽取并再次提交时，系统以此 ID 用最新票位、完整抽取记录和备注覆盖原私有贡献草稿，而不是新增贡献。用户可以点“继续”关闭状态框并继续操作，也可以点“退出”返回导入版面；需要时可通过“我的 → 本地记录”查看尚未完成核对或上传的记录。核对并上传完成后，同一条记录才进入“我的贡献”的已上传子集。前台不等待 OCR 返回，也不显示即时核对结果。

## 2. 后台时延记录

当前仓库只为既有整版识别记录了“单上游调用最多 5 秒、客户端总超时 8 秒”的限制。这不是赏票 OCR 的真实时延测量，也不再影响用户提交后的页面去向。真实基线必须在 V2-08 使用授权样本测得，用于监控和异常处理。

在正常移动网络和经压缩的单张照片下，V2 的初始预算为：

| 阶段 | 预期范围 | 说明 |
| --- | --- | --- |
| 上传与创建私有核对任务 | 0.5—3 秒 | 受图片大小、网络和对象存储影响最大 |
| OCR 与奖级计数 | 1—5 秒 | 必须独立设置上游超时与可观察日志 |
| 本机记录比对与状态写入 | 小于 0.5 秒 | 纯结构化比对与服务端写入 |
| 用户前台等待 | 0 秒 | 提交后立即回到版面；“退出”返回导入版面，“我的贡献”仅由用户通过导航主动查看 |

V2-08 必须记录端到端 p50、p95、上传失败率和不同网络的时延，用于容量、重试与告警策略，不改变“提交后立即回到版面、退出返回导入版面、可主动进入我的贡献”的交互。

## 3. 用户可见状态

这是一个[状态（State）](https://vibe-hub.org/state)流程：每个状态只说明当前记录发生了什么，绝不把“已提交”写成“已发布”。

```text
本地草稿
  ├─ 用户取消 / 权限拒绝 / 上传前失败 → 本地草稿
  └─ 提交 → 后台核对中
                  ├─ OCR 一致 → 核对通过，待发布审核 ── 审核通过 → 已发布
                  ├─ OCR 不一致 → 需要重拍 / 保留本地草稿 / 放弃
                  └─ 网络结果未知 → 正在确认提交状态
```

| 状态 | 用户看到的内容 | 可执行操作 | 公共影响 |
| --- | --- | --- | --- |
| 本地草稿 | 尚未提交 | 返回版面、继续编辑、删除 | 无 |
| 后台核对中 | 已提交，核对会在后台继续 | 在版面继续操作、点“退出”返回导入版面，或导航到“本地记录”查看、取消 | 无 |
| 核对通过，待发布审核 | 记录已提交，等待审核 | 查看状态、请求删除 | 无 |
| 需要重拍 | 未能与记录核对 | 重新拍摄、保留本地草稿、放弃 | 无 |
| 正在确认提交状态 | 网络中断后正在确认是否已收到 | 刷新状态、联系支持 | 无，避免重复提交 |
| 已发布 | 已出现在好版地图 | 查看、请求下线或删除 | 生成一条公共观察 |
| 已拒绝／已下线 | 不会公开或已停止公开 | 查看原因、删除私有证据 | 无或已撤销 |

“核对通过”只代表私有 OCR 核对与状态快照可以保存；“已发布”必须等服务端审核、隐私和新鲜度规则全部通过后才出现。

## 4. 数据最小化与发布内容

为执行 OCR，服务端必须短暂接收私有赏票照片和本机抽取记录的逐奖级计数。这些是核对证据，不是地图展示内容。

核对通过后保存的地图候选只包含：

- 初始版面照片的私有引用与必要的公开脱敏版本；
- 本次核对后计算出的当前版面状态，例如各奖级余票、总余票、价格与 Last 状态；
- 用户授权的位置、地点备注、观察时间、来源和审核状态；
- 最小化的“核对通过”结果与证据引用。

地图不公开用户抽中的具体赏、逐抽记录、赏票原图或 OCR 的逐条文本。它们只能在私有证据包中用于核对、审核、删除和争议处理。

## 5. 失败与幂等

服务端在用户点击提交时以 `boardId` 作为带幂等语义的私有 `ContributionDraft` 键：首次提交创建草稿；同一版面再次提交以最新票位、完整抽取记录、地点和备注原子覆盖该草稿。若网络在上传后断开，客户端进入“正在确认提交状态”，按 `boardId` 查询既有草稿，不能直接重新上传而产生两条贡献。重新导入并确认的版面必须获得新 `boardId`，不得与旧版面合并。

- OCR 不一致：展示可理解的奖级与数量差；不自动改写用户记录，不创建公开地图记录；用户可重拍、保留本地草稿或放弃并删除证据。
- OCR 或上传失败：保留本地草稿；如果服务器已生成私有草稿，则允许取消并删除；不把失败写成“已上传”。
- 后台任务超时或不可恢复：状态转为“需要重拍”，保留失败原因码与最小审计记录；私有照片按保留期或用户删除请求清除。
- 审核拒绝或下线：从地图移除，不改变用户本机抽取记录；可查看原因并请求删除私有证据。

## 6. 实施边界

V1-30A 只演示“提交核对后留在版面显示状态框，并可退出返回导入版面”的前端入口与状态占位；核对与上传完成前的记录只在“本地记录”以未核对／未上传显示，完成后同一 `recordId` 更新为已核对／已上传并进入“我的贡献”派生列表。该低保真不能调用相机、OCR、定位、对象存储、云端保存、点赞服务或地图写入。真实实现依次放在 V2-00（数据、状态和隐私契约）、V2-07（私有上传与任务创建）、V2-08（OCR 评估和时延基线）、V2-09（状态展示、审核与地图发布隔离）。
