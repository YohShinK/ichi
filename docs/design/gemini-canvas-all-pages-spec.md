# ICHI Gemini Canvas 全页面生成规格

> **已被替代（SUPERSEDED）**：本文保留旧 Canvas 研究的历史审计价值，不再作为 V1-29 的视觉、文字或页面壳来源。当前唯一页面壳为 `/Users/cunfu/Downloads/网页 ui.html`，以 `docs/design/v1-29-mobile-visual-direction.md` 为正式迁移规格。

> 用途：将当前 Next.js 网页的页面结构、页面跳转、弹层和状态，交给 Gemini Canvas 生成一个单 HTML 的可交互原型。
>
> 当前源代码：`apps/web/app/page.tsx`、`apps/web/app/styles.css`、`apps/web/app/v1-29.css`

## 给 Gemini Canvas 的总备注

请以当前已经完成的“一番赏版面”页面作为唯一视觉基线，沿用它的视觉语言去设计其余页面：



请把所有页面写在同一个 HTML 文件中。用 URL hash 实现页面路由，例如 `#start`、`#draw`、`#my`；刷新页面后当前 hash 仍能打开对应页面。页面跳转按钮必须使用真实链接或真实 hash 跳转，不能只改变按钮颜色。页面之间共享同一个外壳、视觉 tokens 和导航。

请注意按钮规则：

1. 涉及页面跳转的按钮必须可跳转：`导入版面照片`、`拍摄版面`、`返回`、`开始抽取`、`继续记录抽取`、`管理本地记录`、`建立新的票池`、`打开本地记录`、`查看我的贡献`、`返回我的`、`返回票池首页`、`去拍摄版面`、`重新导入版面照片`、`返回识别结果` 等均必须能跳到指定页面。
2. 计算或业务算法按钮可以只做视觉占位，不必实现真实算法：奖级抽取、`确认`、`开始抽取`、`局面可能性`、`撤销上一抽`、`提交核对`、目标奖勾选后的计算等，不要求接入真实计算、OCR、相机、上传或后端。可以显示按压反馈、打开演示抽屉或短暂状态，但不要伪造真实计算结果或网络完成结果。
3. 弹层关闭、取消、继续等 UI 控件可以实现本地显示／隐藏，不需要页面跳转；`退出`若标记为导航按钮，必须回到 `#start`。
4. 所有按钮都要有可读文字或 `aria-label`，支持键盘焦点；按钮尺寸不能因文案变化而跳动。

## 页面逐项规格

### 1. 导入版面 `#start`

**布局**：页面主体是票券式白色内容卡。上方显示“主流程／导入版面”和副标题“从一张完整的兑换进度板照片开始”。中部放置一个大入口块，标题为“导入版面照片”，说明“拍摄或选择一张完整、清楚的兑换进度板”。下方是浅色提示卡“只保存在这台设备”，说明无需登录、票池和抽取记录保存在当前浏览器、照片不会作为历史附件留下。

**按钮与联动**：

- `导入版面照片` → 跳转 `#camera-capture`；
- `了解计算与隐私` → 跳转 `#method`；
- 底部 `识别` → `#camera-capture`；`好版地图` → `#map-preview`；`我的` → `#my`。

**状态**：首次进入、已有本机记录、窄屏和桌面重排。不要自动调用相机。

### 2. 继续上次记录 `#resume`

**布局**：顶部提示卡“找到上次的票池记录”，显示“大阪店现场 · 2026-08-06”及保存时间“今天 14:32”。下方三格事实数据：当前余票 `37`、累计花费 `¥5,600`、待确认记录 `1 抽`。

**按钮与联动**：

- `继续记录抽取` → `#draw`；
- `管理本地记录` → `#local-records`；
- `建立新的票池` → `#start`。

**状态**：继续成功、没有历史记录时仍保留返回 `#start` 的路径。

### 3. 拍摄版面 `#camera-capture`

**布局**：全屏纵向相机取景区域。中央是虚线版面框，四角有取景角标，框内展示 `Last`、`A 赏` 至 `E 赏` 的简化票面占位；下方提示“请将完整兑换进度版面对准虚线框”。下半屏是独立深色控制区，左侧圆形返回按钮，中央圆形拍摄按钮。

**按钮与联动**：

- 返回箭头 → `#start`；
- `拍摄版面` → `#recognizing`；
- 不调用真实相机或上传，只演示页面流程。

**动效**：取景框轻微呼吸；点击拍摄后短暂淡出并进入识别进度页。

### 4. 正在识别版面 `#recognizing`

**布局**：票券式识别进度页。显示进度条和当前步骤文字，下面是三项清单：`照片已收到`、`奖级与余票已读取`、`价格与 Last 已整理`。完成项显示勾号，当前项高亮，未完成项显示等待状态。

**联动**：页面自动按顺序推进，约 2.5 秒后进入 `#draft`。如果使用 `#recognizing?outcome=cannot-build-pool`，完成后进入 `#cannot-build-pool`。不提供手动继续按钮。

**动效**：进度条递增、清单逐项勾选；不要显示真实 OCR 或网络完成承诺。

### 5. 识别结果 `#draft`

**布局**：这是可编辑的一番赏式识别版面，不使用表格。顶部显示 `Last` 和 `余 1`。奖级按数量自动分为大赏、中赏、小赏：大赏两列方形区块，中赏／小赏使用横向票条。每个奖级显示：奖级名、分类、`总票数 - 已贴票数`、空／实心票位、`总票数` 输入框、`已贴票数` 输入框。

默认数据：A `1/0`、B `2/0`、C `4/0`、D `8/1`、E `16/1`、F `8/0`。

**按钮与联动**：

- `确认`：算法按钮，保持视觉反馈即可；可打开“正在生成版面”遮罩，随后演示跳转 `#draw`；不实现真实生成服务；
- `这张版面拍得不完整` → `#cannot-build-pool`；
- 输入框允许展示编辑状态，但不要求计算守恒。

**生成遮罩**：显示“识别结果已确认”“正在生成版面”、进度条和“正在把奖级、票位和 Last 排成一番赏版面”。输入框和确认按钮在遮罩期间禁用。

### 6. 选择目标奖 `#target`

**布局**：票券式选择区，标题“目标奖”。A 至 F 六个选项以两列网格排列，每项包含复选框和 `A 赏` 等文字，A 默认选中。

**按钮与联动**：

- `开始抽取` → `#draw`；
- 复选框只是展示选择状态，不需要接入概率算法。

### 7. 一番赏版面 `#draw`

这是视觉基线页面，其他页面必须沿用它的票券语言。

**布局**：

- 顶部白色状态卡：`REMAINING`、剩余票数／总票数、单价、`LAST 包套` 和当前包套成本；
- 版面主体：Last 包套信息；大赏使用两列紧凑票券；`Normal Prizes` 分区承载中赏／小赏；
- 每个奖级显示奖级标识、概率、票位格和撕票／贴票视觉；已贴票与空票位明显区分；
- 右侧或右下固定三个圆形快捷按钮：`局面可能性`、`撤销上一抽`、`查看抽取记录`；
- 底部中央固定 `收手` 胶囊按钮，不遮挡底部导航。

**真实页面语义**：奖级按钮目前可模拟一抽，更新票位、余票、概率、累计花费、抽取记录和提示；Gemini 原型不必实现真实算法，但要保留按压、贴票和提示反馈的视觉状态。

**按钮与联动**：

- 奖级卡／票位：算法按钮，可只做按压和贴票演示；
- `局面可能性`：算法按钮，可打开同页抽屉；
- `撤销上一抽`：算法按钮，可显示已撤销状态；
- `查看抽取记录`：可打开记录浮层；
- `收手`：打开分享确认弹层；
- 异形票头和底部导航保持在版面风格内。

**抽取提示**：抽取后显示可关闭、自动消失的同框提示，包括抽到什么赏、剩余票数、累计花费和情境提醒。不要出现“推荐抽几张”“最值得”等促抽文案。

### 8. 局面可能性抽屉

这是 `#draw` 内的弹层，不是独立页面。标题“局面可能性”，显示观察窗口（最多 3 抽）和对应累计成本；列出当前版面事件及概率；底部固定“结果不保证；停止仍可选”。不排序、不推荐、不提供立即抽取按钮。关闭按钮只关闭抽屉。

### 9. 抽取记录浮层

这是 `#draw` 内的弹层。标题“抽取记录”，按最近到最早列出：第几抽、奖级、剩余票数、累计花费。没有记录时显示“还没有新的抽取记录”。关闭按钮只关闭浮层。

### 10. 收手／分享确认弹层

**第一层**：标题“分享本次记录？”，说明“先拍下已抽出的赏票，再和记录核对”。提供 `暂不分享`（关闭弹层）和 `愿意并拍摄赏票`（进入下一层）两个圆形选择按钮。

**第二层**：标题“拍摄赏票”，说明“请把抽完的赏票全部放在框内拍摄”。显示赏票取景框、`地点与备注` 文本框、`提交核对` 按钮和边界说明。`提交核对` 为业务占位按钮，可以只显示提交状态，不调用相机、OCR、定位、上传或后端。

### 11. 已提交状态

仍覆盖在 `#draw` 版面上，不跳独立结果页。显示“已提交”“后台正在核对本次提交”“退出后可导入新的版面”。同一版面再次提交时显示“已更新为当前抽取记录”。

- `退出` → `#start`；
- `继续` → 关闭状态框并留在 `#draw`。

### 12. 账号管理 `#storage`

**布局**：账号状态卡显示“账号管理”“账号与设置 · V2 接入登录与云端保存”，右侧是禁用的“登录功能预留”。下方四项入口：账号与登录、提醒设置、隐私与数据、关于 ICHI。

**按钮与联动**：四项可先统一 → `#method`；`打开本地记录` → `#local-records`；`返回我的` → `#my`。登录按钮保持禁用，仅作占位。

### 13. 本地记录 `#local-records`

**布局**：先显示提示“先看这里”。第一组“需要处理”包含待核对、待审核两条优先记录；第二组“本机草稿”包含当前票池、已抽记录和累计花费。状态 chip 使用“先处理”“待审核”“本地草稿”。

**按钮与联动**：`继续记录抽取` → `#draw`；`查看我的贡献` → `#contributions`；`查看当前状态` → `#storage-fallback`。

### 14. 我的贡献 `#contributions`

**布局**：提示“我的贡献”，说明这里记录主动提交的版面和后台核对／审核进度。显示贡献状态区，可能为：后台核对中、需要重拍、待发布审核。下方显示“已提交的版面”和“已上传（V2 预留）”。

**按钮与联动**：`返回我的` → `#my`；`查看本地记录` → `#local-records`；需要重拍时 `重新拍摄赏票` → `#draw?share=recapture`；`保留本机草稿` → `#local-records`。

### 15. 本地记录已清空 `#deleted`

**布局**：绿色成功提示“本机记录已清空”，说明当前浏览器中的票池、抽取记录和本地草稿已经删除。

**按钮与联动**：`建立新的票池` → `#start`；`返回计算与隐私说明` → `#method`。

### 16. 计算与隐私说明 `#method`

**布局**：三个说明区块：`怎么算`、`照片怎么用`、`记录放在哪里`。分别说明概率来自当前余票和目标、照片只生成可核对信息、V1 记录保存在当前浏览器且没有账号／公共库存／官方背书。

**按钮与联动**：`返回票池首页` → `#start`；`管理本地记录` → `#local-records`。

### 17. 好版地图 `#map-preview`

**布局**：提示“好版地图会在 V2 再来”。明确 V1 不展示地图、门店线索或实时库存判断；下方给出当前可做的导入版面和票池决策方向。

**按钮与联动**：`去拍摄版面` → `#camera-capture`；`返回票池首页` → `#start`。

### 18. 我的 `#my`

**布局**：顶部个人卡，头像字母 `I`、`ICHI 玩家`、`ID: ICHI-LOCAL-001`、`本机模式`。下方六项入口：账号管理、本地记录、我的贡献、提醒设置、隐私与数据、关于 ICHI。

**按钮与联动**：账号管理 → `#storage`；本地记录 → `#local-records`；我的贡献 → `#contributions`；提醒设置／隐私与数据／关于 ICHI → `#method`；`返回票池首页` → `#start`。

### 19. 无法建立票池 `#cannot-build-pool`

**布局**：黄色警告提示“暂时无法建立票池”，说明可能是识别失败、版面不完整或奖级数量不守恒。保持和其他异常页相同的票头、票仓和状态卡风格。

**按钮与联动**：`重新导入版面照片` → `#camera-capture`；`返回识别结果` → `#draft`；`返回票池首页` → `#start`。

### 20. 异常与回退页面

这些页面使用统一的异常状态卡，不生成空白页：

| 页面 | 内容 | 必须跳转的按钮 |
| --- | --- | --- |
| `#undo-protected` | 票池基线已改变，不能安全覆盖后续记录；原记录不会丢失 | `回到版面` → `#draw`；`管理本地记录` → `#local-records` |
| `#storage-fallback` | 浏览器拒绝保存，但当前页面仍保留内存记录 | `重试保存` → `#storage-warning`；`继续当前记录` → `#draw` |
| `#schema-incompatible` | 当前网页无法读取未知版面版本，不执行未知组件或远程代码 | `回到上次可用记录` → `#resume`；`重新导入版面照片` → `#camera-capture` |
| `#storage-warning` | 本机空间不足，当前记录尚未写入 | `管理并清理记录` → `#local-records`；`暂时不保存` → `#draw` |

## 全局交互与动效要求

- 页面切换：轻微淡入或纵向位移动效，不能阻塞导航；
- 票位：点击奖级时可做撕票／贴票动画，但动画结束后不要声称真实算法已完成；
- 识别：清单逐项勾选，完成后自动跳转；
- 识别结果确认：显示生成进度遮罩，再进入版面；
- 抽取提示：从版面上方或中央轻量出现，4 秒后自动消失，也能手动关闭；
- 局面可能性：抽屉打开／关闭；
- 抽取记录：浮层打开／关闭；
- 分享流程：弹层逐层切换，关闭后回到版面；
- 按钮按压：轻微缩放或亮度变化，不能改变布局尺寸；
- `prefers-reduced-motion` 开启时，所有动画降级为即时状态切换。

## Gemini Canvas 不需要实现的内容

- 真实 OCR、相机权限、定位、文件上传、云端核对、账号登录和后端同步；
- 真实概率、组合数、预算、Last 保证或局面可能性算法；
- 真实数据持久化；
- 官方产品图片、Logo、角色或品牌资产。

## 生成后的验收清单

- 所有页面都能从底部导航、页面索引或页面内按钮到达；
- 刷新每个 hash 后页面仍停留在正确视图；
- 所有页面沿用“一番赏版面”的票头、票仓、票位、色彩和动效语言；
- 手机 390px 宽度没有横向溢出，桌面端可以扩展但不破坏手机布局；
- 页面跳转按钮真实可用；算法按钮即使不执行算法，也必须有清晰的视觉反馈或占位状态；
- 不出现“推荐抽几张”“最值得”“保证中奖”等促抽文案；
- 不把按钮、文字、票位、概率或状态做成不可交互的背景图片；
- 所有弹层都有关闭方式，所有禁用状态都有清楚表现；
- 这是一个单 HTML 原型，不依赖远程 Tailwind、Font Awesome、Google Fonts 或运行时下载脚本。
