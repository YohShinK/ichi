# 腾讯地图样式可定制能力分析报告

> 文档状态：`ANALYSIS_ONLY / NO_IMPLEMENTATION`
>
> 调研日期：2026-09-22
>
> 适用对象：ICHI 微信小程序当前使用的微信原生 `<map>`；不等同于腾讯地图 JS API GL、Android SDK 或 iOS SDK。

## 结论摘要

ICHI 当前直接使用微信小程序原生 `<map>`，基础库版本为 `3.17.0`。现有地图没有配置 `subkey`、`layer-style`、`enable-poi`、`enable-building`、个性化图层或可视化图层，因此底图目前采用微信／腾讯地图的默认样式与默认 POI 表现。ICHI 业务点不是腾讯 POI，而是透明原生 marker 锚点上由 `customCallout + cover-view` 绘制的 ICHI Marker。

腾讯地图在小程序端存在两级样式能力：

1. `<map>` 组件提供少量明确的整层开关，例如 `enable-poi`、`enable-building`、`enable-3D`、`enable-satellite`、`enable-traffic`；
2. 付费“地图个性化样式”通过微信公众平台的在线编辑器配置，再以 `subkey + layer-style` 应用到 `<map>`。官方明确说明它能修改背景面、背景线、道路、POI 等元素的颜色和显示层级，并按 POI 类型控制显示／隐藏。

小程序端没有公开“在 WXML 中逐个配置道路、水系、地名、字号、图标”的样式 JSON API。腾讯当前公开文档也没有给出一份稳定完整的“所有底图元素 × 所有可编辑属性”清单。因此本文把能力分为：**官方明确支持**、**控制台条件支持**、**没有公开保证**。视觉方案不能把控制台条件能力当成已经验证可用的接口。

对 ICHI 最合适的方向是：保留低饱和的空间参照，弱化道路／建筑，隐藏绝大多数商业 POI，保留少量行政地名和重要公共交通锚点，让高对比的 ICHI Marker 成为第一视觉层。若不购买个性化地图能力，最有效的降噪手段是关闭整个 POI 层；若购买，则优先按 POI 类型精细隐藏，而不是一刀切删除所有方向感信息。

## 1. 当前 ICHI 地图实现基线

### 1.1 已使用能力

当前 `<map>` 使用：

- 经纬度、缩放级别和 ICHI `markers`；
- `show-location`，仅在位置授权成立时显示定位点；
- 缩放、拖动，关闭旋转和俯视；
- `regionchange`、`markertap`、`callouttap`、`tap`、`updated`、`rendererror`；
- `customCallout` slot，用 `cover-view` 绘制 ICHI Marker；
- `cover-view` / `cover-image` 绘制定位和刷新控件；
- ICHI 自有聚合、展开与选择层级。

当前 marker 的原生 `iconPath` 只是 `alpha: 0`、`1×1` 的透明锚点；用户实际看到的是 ICHI 自绘卡片。当前可见 Marker 主色是黑白、青色 `#20D0B6` 和洋红 `#E6007E`，选中态使用洋红描边。

### 1.2 未使用能力

源码中没有发现以下配置或调用：

- `subkey`；
- `layer-style` / `setting.layerStyle`；
- `styleId` / `mapStyleId`；
- `enable-poi`；
- `enable-building`；
- `enable-satellite`；
- `enable-traffic`；
- `MapContext.addCustomLayer()`；
- `MapContext.addVisualLayer()`；
- QQMapWX 地点搜索、逆地址解析或路线规划 SDK。

由此可知，当前底图中的地名、POI、道路和公共设施都来自默认底图，不是 ICHI 主动查询或绘制的数据。ICHI 产品设计已经明确：地图浏览链路的数据核心是 ICHI `PublicMapLead`，不依赖腾讯地点搜索或店铺数据库。

### 1.3 当前缩放范围

ICHI Marker 交互模型使用 scale `9–18`，地图初始 scale 为 `12`，回到位置时使用 scale `14`。任何底图样式方案都必须至少检查 `9 / 12 / 14 / 16 / 18` 五个倍率，因为腾讯底图会随倍率改变道路、文字和 POI 的密度。

## 2. 腾讯默认底图的视觉元素分类

以下是面向视觉设计的分类，不代表腾讯公开了一套一一对应、名称固定的底层图层 API。实际元素是否出现取决于城市、地图数据、缩放级别、平台渲染和样式模板。

| 类别 | 默认可能包含的元素 | 对用户的作用 | 对 ICHI 的主要噪音风险 |
| --- | --- | --- | --- |
| 基础背景 | 陆地、普通区域、未分类底面 | 提供地图画布 | 低；颜色过亮或偏色会争夺品牌氛围 |
| 道路 | 高速／快速路、主干道、次干道、普通道路、支路、步行路，以及桥梁／隧道等表现 | 建立方向感和可达性 | 中；支路过密、道路高亮会形成强网格 |
| 建筑与区域 | 建筑轮廓／楼块、居住区、商业区、工业区、校园、医院等 AOI 区域 | 提供近场定位参照 | 中到高；密集建筑和区域底色会压低 Marker 可读性 |
| 水系 | 海、江河、湖泊、河道、水面文字 | 城市结构和自然边界 | 低；通常应保留，但需降低饱和度 |
| 绿地 | 公园、林地、草地、自然保护区域 | 城市结构和自然参照 | 低到中；高饱和绿色会与业务状态色竞争 |
| 行政区域 | 国／省／市／区县／街道边界及面填充 | 建立区域层级 | 中；细边界和大面积染色会增加纹理 |
| 地名文字 | 国家、省市区、街道、社区、自然地名、道路名 | 导航和认知锚点 | 高；文字密度会直接与 ICHI Marker 文案竞争 |
| POI 图标与文字 | 餐饮、购物、酒店、医院、学校、景点、生活服务等图标和名称 | 发现现实地点 | 最高；与“抽赏地点探索”业务点最容易混淆 |
| 公共交通 | 地铁线／站、火车站、公交站、机场、港口及相关图标文字 | 方向感和到达参照 | 中到高；重要枢纽有价值，普通站点易造成噪音 |
| 地图装饰 | 道路编号／盾牌、单行等道路符号、区域名底板、比例尺、指南针、定位点、路况、3D 楼块、卫星影像 | 提供地图或导航辅助 | 视元素而定；路况、3D 和卫星不适合 ICHI 主场景 |
| 开发者覆盖物 | marker、label、callout、polyline、polygon、circle、ground/custom/visual layer | 展示业务数据 | 不是默认底图；由 ICHI 单独控制 |

### 3.1 关于透明度的解释

官方小程序组件文档对个性化底图只概括说明颜色、显示层级和 POI 显隐，没有公布每类元素的透明度字段。腾讯位置服务官方示例展示过陆地／绿地填充透明度，因此“面填充透明度”可视为编辑器能力，但不能外推为所有线、文字、图标都能调透明度。设计稿若依赖透明度，必须同时给出“不透明但更浅颜色”的降级值。

### 3.2 关于文字的解释

普通 marker 的 `callout` / `label` 明确支持文字颜色和字号；polyline 文字也明确支持颜色、描边和字号。这些是开发者覆盖物能力，不代表腾讯底图地名和 POI 文字拥有同等接口。对底图文字，当前公开文档没有承诺任意字号、字体家族、字重、字距、描边或排版控制，Gemini 不得把这些当作必然可实施项。

### 3.3 关于图标的解释

开发者自己的 marker、定位点和部分折线箭头可以使用自有图标；腾讯底图自带的 POI／交通／道路编号图标没有公开的“逐类上传替换素材”能力。可行方向是隐藏某类底图 POI，再以 ICHI marker 或业务图层重新表达 ICHI 自有数据，但不能复制或重建一个未经产品授权的腾讯 POI 数据层。

## 4. 微信小程序 `<map>` 样式与图层能力

### 4.1 Custom map style / 个性化地图

微信小程序端的正式接入方式是：

- 在微信公众平台购买并配置“地图个性化样式”；
- 为 `<map>` 配置与样式绑定的 `subkey`；
- 用 `layer-style` 指定该 key 下的样式编号；
- 通过 `bindabilitysuccess` / `bindabilityfail` 识别 `layer-style` 能力是否生效；
- 处理鉴权、网络、内部错误和欠费等失败状态。

`subkey` 的公开文档明确标注为“不支持动态修改”。`layer-style` 可用于选择样式，但上线前仍需真机验证动态切换、冷启动、弱网和能力失败时的回退效果。

### 4.2 `styleId` 不是当前 WXML 属性

对 ICHI 当前平台，应使用的属性名是：

```text
WXML:     subkey + layer-style
setting:  subKey + layerStyle
```

`styleId` / `mapStyleId` 是其他腾讯地图 SDK、JS API 或非正式讨论中常见的叫法，不是当前微信小程序 `<map>` 文档列出的 WXML 属性。后续需求、设计交接和实现任务中应写“个性化样式编号（`layer-style`）”，避免让 Gemini 或工程人员生成错误接口。

### 4.3 组件级图层控制

`<map>` 明确提供以下开关：

| 开关 | 控制范围 | 是否能精细定制 |
| --- | --- | --- |
| `enable-poi` | 整体 POI 点 | 不能按类型；按类型控制要依赖付费个性化样式 |
| `enable-building` | 建筑物 | 整层开关；不能逐栋控制 |
| `enable-3D` | 3D 楼块 | 只有显隐，没有材质样式接口 |
| `enable-satellite` | 卫星底图 | 只有切换，没有重着色接口 |
| `enable-traffic` | 实时路况 | 只有显隐，没有配色接口 |
| `show-location` | 用户定位点 | 定位图标可通过 MapContext 单独替换 |
| `show-scale` / `show-compass` | 比例尺／指南针 | 只有显隐，不能自由换肤 |

不存在对应的 `enable-road`、`enable-water`、`enable-green`、`enable-label`、`enable-admin-boundary` 或 `enable-transit` 开关。这些元素若要弱化或隐藏，只能依赖个性化样式编辑器实际开放的分类。

### 4.4 个性化图层与可视化图层

这两类能力与“个性化底图样式”不同：

- `MapContext.addCustomLayer({ layerId })`：把控制台创建的个性化业务图层叠加到地图；
- `MapContext.addVisualLayer({ layerId, interval, zIndex, opacity })`：叠加可视化图层，可设置刷新周期、绘制顺序和整体透明度；它要求 `<map>` 配置绑定的 `subkey`，并在图层绑定页授权当前小程序 AppID，开发者工具暂不支持。

它们适合展示额外业务数据，不是用来逐项重写腾讯基础道路、水系、地名或 POI 的替代接口。ICHI 当前没有使用这两类图层。

### 4.5 POI 控制

POI 有三种不同概念，必须区分：

1. **腾讯底图 POI**：当前默认可见；可用 `enable-poi=false` 整体关闭；付费样式可按类型精细显隐。
2. **地点搜索返回的 POI**：来自 QQMapWX／地图服务 API，只有 ICHI 主动调用并转成 marker 才会显示；当前 ICHI 没有调用。
3. **ICHI PublicMapLead**：ICHI 自有公开线索，通过自有 marker 展示，不是腾讯 POI。

关闭底图 POI 不会删除 ICHI Marker；但也会同时减少地铁站、医院、商场等方向感参照。若需要“隐藏餐饮购物、保留交通枢纽”，必须使用能按类型编辑的个性化样式，而不是只用 `enable-poi=false`。

### 4.6 marker / callout / customCallout

原生 marker 可定制：

- 图标路径、宽高、旋转、透明度、锚点；
- `zIndex`；
- label 的文字、字号、颜色、边框、背景、内边距、对齐和偏移；
- callout 的文字、字号、颜色、背景、边框、圆角、显示时机和偏移；
- marker 与 POI／其他 marker 的碰撞关系；
- 聚合参与和聚合簇样式。

`customCallout` 用 map 下名为 `callout` 的 slot，将 `marker-id` 与 `cover-view` 绑定。它比普通 callout 灵活，但不是完整 Web DOM：可用元素、层级、动画、合成和真机性能受原生地图限制。ICHI 现有实现已因真机稳定性把 Marker 固定为稳定尺寸，并减少 native binding 替换，因此后续底图视觉方案不得要求高频重绘 customCallout 或把底图样式切换绑到缩放每一帧。

## 5. 不可修改或不应假设可修改的限制

1. **不能在 WXML 中直接提供任意底图样式 JSON。** 小程序消费的是控制台发布后的样式编号，不是 Mapbox 式可自由编程的 style spec。
2. **不能修改腾讯基础数据。** 道路几何、行政边界、建筑轮廓、POI 内容、地名文本和数据更新节奏不由 ICHI 控制。
3. **不能任意决定底图标签排版。** 标注的出现倍率、碰撞避让、换行、密度和具体位置由底图引擎决定。
4. **没有公开保证可改底图字体家族、字重、字距、行高或上传 POI 图标。** 未来控制台即使提供更多选项，也应视为具体产品能力，而不是 `<map>` 稳定接口。
5. **不能任意重排所有底图层。** 个性化样式只允许编辑器支持的显示层级；开发者覆盖物的 `level` 也只有有限枚举。
6. **公共交通不是一个统一开关。** 线路、站点、站名可能分别归入线、POI 或文字分类；是否能分别隐藏必须在实际编辑器检查。
7. **样式能力有商业与鉴权前置。** 当前公开文档说明个性化地图需要购买，并可能因鉴权、网络、内部错误或欠费失败。
8. **默认底图不是稳定视觉资产。** 腾讯可能更新数据和默认渲染；不同城市、倍率、系统和基础库可能有差异。
9. **开发者工具不能代替真机。** 可视化图层明确标注工具暂不支持；底图样式、customCallout 层级和性能也必须在 iOS／Android 真机核验。
10. **不能用“隐藏腾讯 POI”替代产品数据策略。** ICHI Marker 只能展示经过 ICHI 公开资格链路处理的数据，不能因为视觉需要而把第三方 POI 批量转为 ICHI 线索。

## 6. ICHI 推荐地图层级策略

### 6.1 设计目标

地图负责回答“我大概在哪里、附近区域怎么组织”；ICHI Marker 负责回答“哪里有值得探索的抽赏地点”。底图不承担导航、路线规划或完整城市检索，因此应从“导航信息最大化”转为“空间参照最小充分”。

### 6.2 推荐保留、弱化与隐藏

| 元素 | 策略 | 理由 |
| --- | --- | --- |
| 陆地／基础背景 | 保留 | 提供稳定画布，与页面 `#E8E9E5` 接近但需有轻微区分 |
| 水系 | 保留、低饱和 | 江河湖海是最有效的城市结构锚点，且通常不与 Marker 文案竞争 |
| 绿地／大型公园 | 保留、明显弱化 | 提供区域认知；避免高饱和绿色与 ICHI 青色强调色竞争 |
| 高速／快速路／主干道 | 保留、弱化 | 提供跨区域方向感；线宽和对比不应超过 ICHI Marker 边缘 |
| 次干道 | 保留但进一步弱化 | 在 scale 14–18 提供近场定位，不应形成深色网格 |
| 普通道路／支路 | 低对比；低倍率尽量少 | 近场有用，高密度时是主要背景噪音 |
| 建筑轮廓 | 弱化或关闭 | ICHI 不是步行导航；密集楼块会让 Marker 卡片边缘难辨 |
| 3D 楼块 | 隐藏 | 透视、阴影和遮挡会破坏 Marker 的稳定视觉层级 |
| 行政边界 | 仅保留高层级、低对比 | 区级边界有助于浏览，街道级细线通常没有收益 |
| 省／市／区地名 | 保留，减少层级 | 提供区域方向感；优先区名，不追求完整街道／社区标签 |
| 道路名称 | 适量保留 | 近场确认位置有价值，但颜色需低于 ICHI Marker 次级文字 |
| 商业／餐饮／购物／生活服务 POI | 隐藏 | 与 ICHI“抽赏地点”最易混淆，也是最大的图标和文字噪音来源 |
| 学校／医院／景点等普通 POI | 默认隐藏或极弱 | 只作为方向参照，不应与 ICHI Marker同等突出 |
| 地铁／火车／机场等重要枢纽 | 有选择地保留 | 是用户到达抽赏地点的重要参照；优先保留大站和线路，隐藏普通公交站 |
| 公交站／地铁出入口等细粒度设施 | 隐藏 | 数量多、图标密，ICHI 不承担最后 100 米导航 |
| 实时路况 | 隐藏 | 与探索任务无关，红黄绿高饱和颜色会与业务状态竞争 |
| 卫星影像 | 隐藏 | 纹理过强，文字和 Marker 对比不可控 |
| 比例尺／指南针 | 默认隐藏 | 当前没有旋转／俯视，指南针价值低；比例尺不是核心决策信息 |
| 用户定位点 | 保留 | 支持“我附近”的基本参照；视觉必须次于 ICHI Marker |

### 6.3 推荐视觉层级

从后到前：

1. **L0 画布**：暖灰中性背景；
2. **L1 自然结构**：低饱和水系、绿地；
3. **L2 空间骨架**：行政高层边界、主／次干道、弱化建筑；
4. **L3 参照文字**：区名、少量道路名、重要交通枢纽；
5. **L4 ICHI Marker**：默认业务点与聚合点；
6. **L5 选中 Marker / spiderfy**：洋红选择态和最高 marker 层级；
7. **L6 页面 UI**：搜索、筛选、状态、详情卡、定位／刷新、Bottom Nav。

底图任一元素都不应使用与 ICHI Marker 相同的高饱和洋红或青色。底图文字和线条不能在静态截图中比 Marker 的 `#191A20` 主块更抢眼。

### 6.4 建议颜色方向

以下是供 Gemini 出方案的起点，不是最终样式值；必须在腾讯在线编辑器可表达的范围内收敛：

| 元素 | 建议方向 | 参考值 |
| --- | --- | --- |
| 陆地／背景 | 接近现有界面暖灰，避免纯白大底 | `#ECEDE9` / `#F1F2EF` |
| 建筑 | 与背景仅有轻微明度差 | `#E2E3DF` / `#E6E6E2` |
| 主道路填充 | 中性浅色 | `#FAFAF8` |
| 道路边线 | 低对比冷灰 | `#D5D7D3` |
| 次级／普通道路 | 比主路再弱一级 | `#E0E1DD` |
| 水系 | 灰蓝、低饱和 | `#D9E7EA` |
| 绿地 | 灰绿、低饱和 | `#DFE8DD` |
| 行政边界 | 细、低对比中灰 | `#C9CBC6` |
| 主要地名 | 中灰，不用纯黑 | `#666A66` |
| 次级地名／道路名 | 更浅的中灰 | `#858985` |
| 重要交通锚点 | 单一中性蓝灰；不要使用 ICHI 洋红／青色 | `#6F7E86` |

如果编辑器不支持某项透明度，应直接使用更接近背景的实色降级，不能通过在 `<map>` 上覆盖一层半透明普通 view 来整体“洗白”底图；这种做法可能影响对比、点击、原生层合成和真机一致性。

### 6.5 实施优先级建议

后续若决定接入，建议按以下顺序做独立任务，不在本报告中实施：

1. 在微信公众平台确认个性化地图购买状态、样式编辑器实际分类和计费／授权边界；
2. 先制作一套低噪音浅色样式，只调整底图，不改 ICHI Marker；
3. 优先处理 POI 类型显隐，再处理色彩；
4. 在 scale `9 / 12 / 14 / 16 / 18` 截图比较默认底图与候选样式；
5. iOS／Android 真机验证 `layer-style` 成功、失败回退、弱网和冷启动；
6. 验证 Marker、customCallout、定位点、覆盖 UI、点击和地图手势没有层级或性能回归；
7. 只有人工视觉验收通过后，才把样式编号接入正式代码。

## 7. Gemini 制作视觉方案时必须遵守的约束

1. **只设计底图表现，不重构产品。** 不改搜索、筛选、详情卡、导航、Marker 信息结构、聚合逻辑、spiderfy 或定位行为。
2. **把 ICHI Marker 当作最高信息优先级。** 底图只能提供空间参照，不能出现与 Marker 等权重的彩色图标、深色标签或大面积高饱和块。
3. **不得输出虚构接口。** 小程序接入名必须写 `subkey + layer-style`；不得要求使用 `styleId`、任意 JSON style 或 CSS 选择器修改原生底图。
4. **不得假设任意底图字体可定制。** 字体家族、字重、字距、换行、避让和精确字号都不是公开保证；方案必须在默认字体和默认排版仍存在时成立。
5. **不得设计自定义腾讯 POI 图标。** 可以建议按类型隐藏／保留，但不能要求替换腾讯图标素材。ICHI 自有图标只能用于 ICHI 自有 marker 或覆盖物。
6. **不得依赖任意图层重排。** 只使用编辑器允许的底图显示层级，以及 marker `zIndex`／覆盖物有限 `level`；不能要求把某个腾讯标签精确放到两个业务子层之间。
7. **同时给出能力降级。** 每一项透明度、分类显隐、标签样式建议都要给出“若控制台不支持”的实色或整体开关方案。
8. **保留最低限度方向感。** 至少保留水系、主路、区级地名；重要交通枢纽可保留，普通商业 POI 和公交站优先隐藏。
9. **禁用导航型视觉。** 不使用实时路况、卫星影像、3D 楼块、路线高亮、转向箭头或导航蓝线作为默认地图表现。
10. **避免占用 ICHI 语义色。** 底图不得大量使用 `#E6007E`、`#20D0B6`、近黑 `#191A20`；这些颜色留给 Marker、选择态和业务信息。
11. **覆盖完整倍率。** 至少提供或评估 scale `9 / 12 / 14 / 16 / 18`，不能只交一张固定倍率效果图。
12. **分别展示三种密度场景。** 空旷区、普通城区、核心商圈各一张；验证 POI 和文字不会在高密度区域淹没 Marker。
13. **考虑原生组件边界。** 不要求 customCallout 每帧动画、滤镜、复杂混合模式或依赖 DOM 的效果；不能用全屏蒙层假装修改底图。
14. **保留失败回退。** 个性化样式鉴权失败时会回到默认地图；搜索、Marker 和详情必须仍然可用，不能依赖特定底图色才能看清。
15. **设计稿要标注“可实施等级”。** 每个视觉建议标记为“组件硬开关”“个性化编辑器待确认”“ICHI 覆盖物可实现”或“不可实现”。

## 8. 能力决策建议

### 推荐方案 A：购买个性化地图能力

最符合 ICHI。通过样式编辑器按 POI 类型隐藏餐饮、购物、生活服务和普通公共设施，保留区级地名、主／次干道、水系与重要交通枢纽；同时把底图整体改成低饱和暖灰。优点是降噪精细、方向感损失小；代价是购买、配置、鉴权、真机验证和持续运营成本。

### 降级方案 B：只使用免费组件级开关

保持默认底图配色，但关闭 `enable-poi`，继续关闭 3D、卫星、路况、旋转和俯视，并评估是否关闭建筑。优点是实现简单、接口明确；缺点是 POI 全关会连同部分重要交通参照一起消失，且道路、地名、水系颜色仍不能调整。

### 不推荐方案 C：页面蒙层“洗白”地图

不建议在原生 `<map>` 上增加半透明遮罩来伪造浅色样式。它不能按元素降噪，会同时降低 Marker 和定位点对比，还可能造成点击、同层渲染、层级与不同设备合成差异。
