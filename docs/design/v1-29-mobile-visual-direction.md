# V1-29 网页壳迁移规格

> 状态：`APPROVED`。本规格及其 Next.js 页面实现已随 V1-29 于 2026-08-11 通过用户人工验收。`/Users/cunfu/Downloads/网页 ui.html` 是完整页面壳和视觉事实源；此前任何 V1-29 的 image2、深色票券、颜色、组件风格或动效描述，均不再构成实现与验收约束。V1-E 必须把该完整网页基线一比一照搬到微信小程序，只允许必要的平台语法／API 适配。

## 迁移原则

1. 将 `网页 ui.html` 作为原始 HTML 页面壳直接由 Next.js 托管；其既有页面文字、字体、字号、图标、字符样式、信息层级、布局、尺寸、色值、圆角、阴影与动效逐项保留。
2. 源网页不是“参考图”或局部灵感；它是 ICHI 网页工作台本身，未经用户新指令不得用手写 JSX/CSS 近似、改写或替换其中已有 UI 信息和内容。
3. ICHI 已批准的功能必须接入语义对应的源控件：页面路由、识别进度、识别结果修正、目标选择、奖级分类、抽取、撕拉、概率、累计花费、最近 50 抽撤销、情境提醒、局面可能性、抽取记录、收手、提交核对、本地记录、我的贡献与账号框架。
4. 只有源网页没有覆盖、但 V1-D 已批准的功能，才可补充界面；补充界面必须复用该源网页的视觉语言，不得重新引入旧 V1-29 风格。
5. 当用户明确要求修复跨页面的无意版式漂移时，统一依据 [`v1-29-ui-design-tokens.md`](./v1-29-ui-design-tokens.md) 调整参数层；该规则不允许替换原壳的文字、字体、图标资产、色彩语言或交互含义。
6. 导入 Hero 的相机图标按用户新指令可以移除外部白色画布，使用透明 PNG 直接贴入底板；黑白图标主体与其含义不变，画布尺寸沿用原先视觉资产尺寸，以保持与地图标识接近的可见主体大小。

## 本地实现边界

- 保持 Next.js App Router 与已有本地计算／缓存模块；为确保用户指定的绝对保真，当前直接托管原始 HTML 页面壳，不以截图或图片替代可操作控件。
- 源文件内的 Tailwind CDN、Font Awesome、Phosphor 与 Google Font 作为用户批准的保真运行时输入保留；后续若改为本地化依赖，必须先得到用户明确许可并经截图逐项核对。
- 动态数值来自 ICHI 当前版面状态；源网页中原本的静态演示数值可由真实识别与抽取状态替换，但其信息位置与表达结构保持一致。
- 390px 宽手机端为首要验收视口；底部 `识别／地图／我的` 导航保留，桌面仅允许源网页已有的自适应导航形态。

## 功能映射

| 源页面／控件 | 接入的 ICHI 行为 |
| --- | --- |
| 导入与拍摄版面 | 进入纵向取景框，拍摄后启动识别流程 |
| 正在提取版面 | 逐项展示本地识别进度，成功自动进入核对，失败自动进入统一失败页 |
| 核对结果与确认并生成版面 | 直接修改总数／已贴数，生成时显示进度，完成后进入目标奖选择 |
| 选择目标奖 | 多选目标奖并更新工作台的目标相关提示／局面可能性 |
| 一番赏版面 | 显示本地派生的大／中／小赏，撕拉记录抽取，刷新概率与累计金额 |
| 局面可能性、撤销、记录 | 调用既有 `board-outlook`、50 步撤销与抽取记录状态 |
| 决定收手与提交核对 | 展示取证／备注前端流程，按同一 `boardId` 覆盖本机贡献快照，提交后仍留在版面 |
| 我的、本地记录、我的贡献 | 保持账号框架；本地记录展示同一记录模型的全集与核对／上传双状态，我的贡献只筛选已上传子集并预留点赞计数 |

## 验收

- `网页 ui.html` 的每个已存在页面、控件文字和可见信息均可在 Next.js 中找到对应实现。
- 所有路由和已有 ICHI 交互仍可操作，业务状态不能被静态图片化。
- 无远程 UI、图标或字体运行时依赖；窄屏无横向溢出。
- 通过 Next.js 构建、类型、Lint、格式、Vitest、Playwright、真实浏览器路径与工作流校验后，等待用户对全局视觉壳进行人工验收。
