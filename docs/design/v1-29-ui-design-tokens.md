# V1-29 UI Design Tokens

> 状态：`APPROVED`。本规范已随 V1-29 于 2026-08-11 通过用户人工验收；服务于完整网页基线及其小程序一比一照搬，不改写产品文案、业务路径或算法，也不把所有页面强行做成同一张卡片。

## 1. 目的与使用方式

`网页 ui.html` 仍是页面信息、字体、图标、色彩、动效和基础组件语言的事实源。本文件补上源网页未明确写出的**版式秩序**：哪些数值必须复用、哪些差异是有意保留的、以及新增页面如何落位。

实现时先使用本文件定义的变量和页面族规则；只有内容语义不同，才使用下文的变体。不得为了“统一”而改变已批准的按钮含义、图标资产、交互路径或文字。

## 2. 画布与全局定位

| Token                          |                      值 | 规则                                                                                                                 |
| ------------------------------ | ----------------------: | -------------------------------------------------------------------------------------------------------------------- |
| `--ichi-page-gutter`           |                  `16px` | 普通页面左右内容边距。全宽相机、模态遮罩除外。                                                                       |
| `--ichi-top-safe-area`         |                  `40px` | 所有页面第一个可见组件的顶部起点；以“好版地图”主卡顶边为基准。不能被标题、图标、相机构图角标、吸顶栏或动画向上越过。 |
| `--ichi-bottom-nav-offset`     |                  `20px` | 底部导航距视口底部的固定距离，所有页面一致。                                                                         |
| `--ichi-bottom-nav-height`     |                  `64px` | 导航外壳高度；内容区需要避让时使用其与 bottom offset 的合计 `104px`。                                                |
| `--ichi-visual-center-shift-y` |                 `-32px` | 从物理视口中心向上修正的距离，等于 `(top safe area − bottom nav clearance) ÷ 2`。                                    |
| `--ichi-visual-center-y`       | `calc(50dvh + shift-y)` | 去掉顶部安全区与底部导航占用后的可用内容区中心；需要“放在视觉中心”的组件以自身中心对齐此位置。                       |
| `--ichi-draw-status-height`    |                  `92px` | 一番赏工作台顶部余票／Last 状态栏的固定高度；滚动内容从该高度加 `space-5` 后开始。                                   |
| `--ichi-draw-edge-fade-size`   |                  `56px` | 工作台顶部遮罩从顶部安全区向状态栏内收的渐隐长度；最上沿必须为完全不透明，滚动内容到达视口顶边时不可见。       |
| `--ichi-draw-bottom-fade-height` | `nav-height + offset` | 工作台底部导航上沿向下的渐隐范围；覆盖导航本体与底部安全距离，避免赏票在半透明导航后仍然突出。                 |
| `--ichi-hold-duration`         |                 `500ms` | “决定收手”的长按确认时长；未完成即释放时不得触发。                                                                   |
| `--ichi-share-center-offset-y` |                  `24px` | 共享选择卡相对视觉中心的下移修正；其操作组较重，使用该偏移让整张卡的视觉重量落在中心附近。                             |
| `--ichi-page-max-width`        |                 `448px` | 手机单列内容上限；更宽屏幕只增加两侧留白，不拉长正文或按钮。                                                         |

普通页的开始位置由 `top safe area + page gutter` 决定。相机页的顶部安全区必须保持灰白页面背景，黑色取景区从 `top safe area` 下方开始；四个构图角标相对黑色取景区使用相同的 `20px` 左右内距，导航仍使用同一底部锚点。

### 2.1 视觉中心定位

“放在视觉中心”不是把组件放进浏览器的几何正中心，而是把**组件自身的中心**对齐到 `--ichi-visual-center-y`。该位置以顶部安全区为上界、以底部导航避让区为下界，因此不会被顶部留白或底部导航挤偏。实现时使用 `top: var(--ichi-visual-center-y)` 加 `transform: translateY(-50%)`；不得用文档流中的 `margin-top` 猜测位置。

当前引用该 token 的组件：`正在提取版面`识别加载卡、局面可能性模态卡、抽取记录模态卡。后续只要用户要求组件“放在视觉中心”，就复用这一对 token 与定位方式。

共享选择属于带三条分支的决策卡，卡片自身中心使用 `visual center + share center offset`；这是一项记录在案的语义变体，不允许用页面滚动或临时 `margin-top` 调整。

## 3. 基础尺度

| 名称       |     值 | 用途                                      |
| ---------- | -----: | ----------------------------------------- |
| `space-1`  |  `4px` | 图标与极短辅助文字。                      |
| `space-2`  |  `8px` | 行内元素、紧凑状态。                      |
| `space-3`  | `12px` | 标题与正文、列表的紧凑分隔。              |
| `space-4`  | `16px` | 卡片组、双按钮组、同级区块。              |
| `space-5`  | `20px` | 图标与标题的普通分隔。                    |
| `space-6`  | `24px` | Hero 图标与标题、正文与动作区的默认分隔。 |
| `space-8`  | `32px` | 大卡片内边距、页面级区块分隔。            |
| `space-10` | `40px` | 强信息卡的垂直内边距或视觉呼吸区。        |

禁止出现只为“看起来差不多”而新增的 `13px`、`19px`、`27px` 等孤立值；例外必须记录为具体组件的视觉资产尺寸。

| Token                           | 值／来源                | 使用规则                                               |
| ------------------------------- | ----------------------- | ------------------------------------------------------ |
| `surface-page`                  | 源网页 `#f0f2f5`        | 全局灰色画布。                                         |
| `surface-card`                  | 源网页 `.light-capsule` | 普通信息与 Hero 卡。保留原有高光、内阴影和暖／冷渐层。 |
| `ink-primary`                   | 源网页 `#111111`        | 标题、主要数字、主按钮。                               |
| `ink-secondary`                 | 源网页 `zinc-500`       | 正文、说明、非主状态。                                 |
| `accent-pink` / `accent-purple` | 源网页按钮光晕          | 仅用于主行动边缘反馈与强调状态，不能替代文字状态。     |
| `radius-card`                   | `32px`                  | 普通胶囊／信息卡。                                     |
| `radius-hero`                   | `40px`                  | 单页核心 Hero 卡，例如导入、地图、异常恢复。           |

## 5. 排版规则

| 层级           |  源壳字号 | 行高／宽度规则                                                           |
| -------------- | --------: | ------------------------------------------------------------------------ |
| Hero 标题      |    `24px` | 单行优先；两行时保持居中，最大 `300px`。                                 |
| 普通页标题     | `24–30px` | 页面标题左对齐；标题到说明为 `space-2` 或 `space-3`。                    |
| Hero／说明正文 |    `12px` | `line-height: 1.5–1.6`，最大阅读宽度 `290px`，居中 Hero 不超过两到三行。 |
| 菜单／卡片标题 |    `14px` | 与 40px 图标同一基线组，行内间距 `space-4`。                             |
| 标签／辅助信息 |  `9–11px` | 只承载状态或单位，不能替代正文说明。                                     |

正文宽度由阅读节奏决定，不等同于按钮宽度：Hero 正文最多 `290px`，全局长条主按钮最多 `288px`；窄屏时两者都允许缩至父容器宽度。所有长条主按钮都必须比底部导航外壳窄，字符放不下时优先减少字号一级，不得重新拉满视口。

## 6. 页面族

### 6.1 Hero 主行动页：导入、地图、异常恢复

共同规则：

1. Hero 卡从顶部安全区开始，使用 `radius-hero`。
2. 卡片左右内边距 `24px`；垂直内边距按内容密度使用 `32px` 或 `40px`。
3. 内容顺序固定为：图标／视觉资产 → 标题 → 说明 → 行动组。
4. 普通 Hero 的标题与说明之间 `12px`；说明与第一主按钮之间 `24px`；主、次按钮之间 `16px`。异常恢复卡使用下方专属垂直节奏覆盖这些普通 Hero 数值。
5. 行动组居中且最大宽度 `288px`；主与次按钮同宽、同高 `52px`。

导入版面 Hero 的行动组是该页面族的双操作变体，卡片本身不使用吉祥物水印。上方“进入辅助抽赏”使用既有黑色主胶囊和玫红／紫色边缘光晕，下方“仅上传版面”使用同尺寸灰色次胶囊；两者垂直间距固定为 `12px`，都位于 Hero 内部且不得压入下方“抽赏草稿”页头。两个按钮都使用 `20px` 前置图标，图标与文字间距固定为 `8px`；辅助抽赏沿用白色扫描图标，仅上传版面使用黑色描线的“圆环内向上箭头”图标。两个图标必须保持相同视觉重量：上传图标在 `256×256` 源画布使用 `24` 单位圆角描边，缩放到 `20px` 后等效线宽约为 `1.875px`，与扫描图标的主体线宽一致。新增第二个按钮时只增加行动组高度，不缩放 `142px` 导入视觉资产、标题、说明或按钮文字。

V1-F 的每日识别额度组件固定在导入 Hero 左上角：外径 `38px`、内径 `30px`，圆环中心只显示 `remaining / limit`，不在旁边重复“今日识别额度”、同步状态或剩余次数文字。组件脱离标题与双操作的正常文档流，Hero 恢复既有紧凑高度，两个按钮随之上提。进度使用服务端返回的 `used + reserved`；查询值只用于展示，二次确认照片时仍由服务端预占。额度耗尽使用“无法建立票池”异常卡节奏与感叹号图标，唯一动作是“重新导入照片”，不得隐藏下方抽赏草稿。

允许的语义变体：

| 变体     | 视觉资产                           | 图标到标题 | 原因                                                   |
| -------- | ---------------------------------- | ---------: | ------------------------------------------------------ |
| 导入版面 | 用户提供的相机／ICHI 图标，`142px` |     `12px` | 草稿区加入后采用紧凑 Hero；图标仍是独立任务插画，不放在标题上或遮盖标题。 |
| 地图预告 | `96px` 圆形地图图标                |     `24px` | 它是页面标识，尺寸更小以让 V2 功能说明成为焦点。       |
| 异常恢复 | `80px` 状态图标                    |     `24px` | 以“无法建立票池”卡片的实际排版为统一基准。             |

异常恢复页与异常阻塞弹窗统一采用“无法建立票池”的**异常状态卡片内部垂直节奏**。以下数值是这一页面族的专属 [设计令牌](https://vibe-hub.org/design-token)，覆盖上方普通 Hero 的默认间距：

| Token                                  | 值     | 测量边界／用途                                                   |
| -------------------------------------- | -----: | ---------------------------------------------------------------- |
| `--ichi-exception-card-padding-y`      | `40px` | 卡片顶部与底部内边距；最后一个按钮下沿到卡片下沿同为该值。       |
| `--ichi-exception-icon-size`           | `80px` | 黑色圆形状态图标底板。                                           |
| `--ichi-exception-icon-glyph-size`     | `36px` | 圆形底板内的白色描线语义图标。                                   |
| `--ichi-exception-icon-title-gap`      | `24px` | 图标底沿到主标题上沿。                                           |
| `--ichi-exception-title-copy-gap`      | `10px` | 主标题下沿到小字说明上沿。                                       |
| `--ichi-exception-copy-actions-gap`    | `28px` | 小字说明最下沿到第一个按钮上沿。                                 |
| `--ichi-exception-action-gap`          | `12px` | 第一个按钮下沿到第二个按钮上沿。                                 |
| `--ichi-exception-action-height`       | `52px` | 主、次按钮的统一高度。                                           |
| `--ichi-exception-action-max-width`    | `288px`| 动作组与按钮的最大宽度；窄屏时允许收缩至卡片内容宽度。           |

单按钮卡片省略第二个按钮及其对应的 `12px` 间距，仍保留 `40px` 的最后按钮下沿到卡片下沿距离；双按钮卡片完整使用五段节奏。卡片不得用固定高度制造多余空白，异常弹窗同样由内容与上述间距自然撑开。

状态 [图标](https://vibe-hub.org/icon) 只统一视觉容器，不统一语义：警告／不兼容／容量不足使用白色感叹号，撤销保护使用白色撤回箭头，存储读取异常使用白色数据库，记录清空使用白色垃圾桶。禁止把这些图标全部替换成信息 `i`、字符占位或与状态无关的通用图形。

### 6.2 信息卡与菜单行：本地说明、我的、方法页

- 卡片使用 `radius-card`，内部留白 `16–24px`；同一张卡的行间距为 `0`，由行自身高度建立节奏。
- 菜单行最小高 `56px`，左右内边距 `12px`；40px 圆形图标、标签、右侧箭头构成一个水平组。
- 图标到标题 `16px`，标题到右箭头不设置视觉性空白，使用 `justify-between` 保持末端对齐。
- 两张并列的卡片组之间为 `12–16px`；卡片内标题到说明 `8px`，说明不超过三行。
- 识别首页不显示泛化的“只保存在这台设备”说明卡。页面由固定的紧凑导入 Hero 与下方可滚动草稿区组成；Hero 不参与草稿滚动，草稿区使用剩余可用高度并避让底部导航。
- 每张“抽赏草稿”横向胶囊卡和后续生成的抽赏记录卡都放置轻提醒大赏四芒星眼吉祥物白色水印；直接上传生成的上传记录不使用该水印。水印由 `ichi-mascot-large.png` 确定性派生 `ichi-mascot-large-watermark.png`，主体变为白色，原四芒星眼的白色像素转成透明镂空，并使用极淡轮廓投影保证整体轮廓在白卡上可见；尺寸固定为 `180×143px`，`opacity: 0.432`，相对初版向左移动 `36px`、向下移动 `14px`，并从 `-45deg` 顺时针旋转 `5deg` 至 `-40deg`。水印由卡片自身 `overflow: hidden` 裁切，不得露出卡片外，也不得覆盖正文、状态或操作的可读性和命中区域。
- 识别首页草稿与“我的记录”中的记录使用同一 Swipe-to-Delete 范式：卡片左滑后向左停靠 `72px`，右侧揭示黑底白色简约垃圾桶。本机记录按相同 `boardId` 同步刷新两处列表；云端规范记录的垃圾桶触发 owner-scoped 服务端删除，成功受理后再移除本地投影，旧 Storage 不得覆盖云端事实。
- “我的”二级页使用统一页头：页头整体高 `52px`，`52px` 灰色圆形返回按钮的上缘与页面顶部安全区对齐，按钮无边框、无内阴影；右侧只显示黑色、`24px` 的页面主标题，不再显示灰色说明副标题。该规则适用于账号管理、我的记录、我上传的版面、提醒设置和隐私与数据，不依赖页面底部是否另有返回操作。
- “我的”二级页正文使用独立滚动容器；返回按钮、主标题和存在的统计栏均位于滚动容器外。记录页统计栏使用“全部有 X 个 · 现在已上传有 Y 个 · 未上传有 Z 个”的状态句式，并在记录增长时保持固定。
- 可选资料编辑卡只由用户在“我的”页主动点击头像或昵称打开：卡宽上限 `332px`，内边距上／左右／下为 `28px / 24px / 30px`；头像选择命中区为 `76×76px` 圆形，标题到说明沿用状态卡文字层级，昵称输入高 `44px`、圆角 `12px`。主行动在昵称没有变化且未重新选择头像时使用灰底禁用态且不显示光晕；发生任一有效变化后恢复黑底白字与既有胶囊光晕。卡片左上 `18px` 放置 `40×40px` 灰底圆形返回按钮，取消编辑立即返回“我的”且不影响基础功能。首次首页与两个新版面入口不得自动显示该卡。账号管理页不重复放置头像选择、绑定按钮或“已绑定”状态说明。“我的”页资料组使用 `80px + minmax(0, 1fr)` 两列、`16px` 列间距，头像左沿与下方卡片左沿一致；头像按钮不得保留微信原生自动外边距，文字列固定左对齐并允许收缩，禁止向右溢出。
- 全部纵向正文滚动区沿用“局面可能性”正文的原生边界弹性与系统阻尼：顶部／底部越界拖动可短暂延伸并在松手后自然回弹；禁止在 `scroll` 过程中逐帧 `setData` 回写或把负向过拖立即钳制到 `0`。需要恢复位置时，只在滚动、惯性和回弹完全结束后保存稳定 `scrollTop`。
- 底部“我的”标签在上述二级页中再次点击时，回到“我的”根页；识别标签继续恢复最近稳定识别状态，地图标签不增加重复点击行为。

### 6.3 表单、识别与工作台

- 页面标题和首个可编辑模块均从顶部安全区开始；标题到首模块 `16px`。
- 相同尺寸的输入格／奖级格使用同一行内 `8px`、组间 `12–16px`，但大奖方格与中／小赏横条仍按奖级密度规则呈现。
- 工作台是可滚动内容页；吸顶余票卡、右侧快捷按钮和“收手”按钮必须避让底部导航，不得借滚动改变固定控件位置。
- 工作台固定层分为三组：余票／Last 状态栏固定在 `top safe area`；局面可能性、撤销、抽取记录固定在视口右侧；“决定收手”固定在底部导航上方。三组都脱离奖级票面滚动层，页面动画不得通过 `transform` 把它们重新变成内容区定位。
- 抽取后的轻提醒保持页面壳原有水平居中；其垂直中心固定为 `top safe area + draw status height / 2`，与顶部余票／Last 状态栏的垂直中心对齐，不通过左右位移模拟对位。大赏、中赏和小赏的轻提醒吉祥物统一以中心为原点旋转 `-3deg`，只切换表情素材，不改变倾角。
- 工作台滚动边界使用两段非交互渐隐：顶部渐隐层覆盖顶部安全区与状态栏的固定区域，从视口最上沿的完全不透明页面背景开始，向下平滑退回透明；滚动赏票到达最上沿时必须完全消失，遮罩不得向状态栏下方的赏票区域延伸。底部渐隐层从底部导航上沿向下延伸到 `draw-bottom-fade-height`。渐隐层必须 `pointer-events: none`，只降低固定区域附近的视觉突出度，不改变固定控件和赏票的交互。
- 局面可能性、抽取记录、分享选择和提交状态使用统一的阻塞式模态范式：遮罩层级为 `z-index: 300`，覆盖并禁用顶部状态、右侧快捷操作、底部长条操作和底部导航；标准卡宽上限 `340px`、高 `420px`，卡片自身中心对齐 `visual center`。局面可能性与抽取记录的模态页头必须占满卡片内容宽度，最小高度 `40px`；标题位于左侧并为关闭按钮预留宽度；`40px × 40px` 圆形关闭按钮必须相对整张模态卡以 `top: 24px; right: 24px` 绝对锚定在右上角，并与标题首行垂直对齐。不得再用 `flex`、`space-between` 或自动左外边距推算其横向位置，也不得让按钮按标题内容宽度停在卡片中部。溢出内容只在卡片正文中滚动。任何确认、取消、退出或路由动作都必须先关闭当前模态，不能把模态带到下一页。
- 抽取记录正文使用网页原壳的白底分隔行：记录行上下内边距 `12px`、相邻行间距 `12px`，只保留 `1px` 黑色 `5%` 分隔线，不使用灰色底板或圆角。左组间距 `16px`，`#序号` 为 `12px` 灰色等宽粗体，赏级为 `16px` 黑色 `900`；右组垂直右对齐，“余 N”为 `10px` 灰色粗体，累计金额为 `14px` 玫红 `900`。
- “决定收手”采用按住确认：默认白底黑字，按住后黑色在 `500ms` 内从左向右填充；填充覆盖到的图标和文字使用同宽遮罩同步变为白色。达到 `hold duration` 才打开下一层；提前松开、移出或手势取消时立即回到 0%，不保留半完成状态。
- 共享选择卡的主按钮进入拍摄；次按钮“继续抽赏”关闭卡片并留在工作台；最下方“暂不分享并退出”使用 `10–11px` 灰色文字和灰色虚线下划线，保存草稿后返回识别首页。三条操作均不得借独立页面表达。
- 识别中的进度面板是居中状态层：其中心必须对齐 `--ichi-visual-center-y`，而不是浏览器文档中心。
- 识别结果与目标奖页面使用固定页头、独立可滚动内容区和固定主行动。所有识别出的 A—F 赏以双列卡片呈现；识别结果字段固定为“总票数／已贴的票数”，目标奖选项都可多选且未选状态外观一致。
- “总票数／已贴的票数”输入框使用可为空编辑态：连续删除必须能让框内完全无文本，空值不得被即时归一化成 `0` 或 `1`。总票数提交下限为 `1`；已贴票数允许显式填写 `0`，但不允许为空、为负数、非整数或超过对应总票数。编辑态中的空值可以进入本机识别流程快照以支持页面恢复，但不得转换为正式票池。
- 识别结果的顶部元数据卡按“IP → 单抽价格 →（仅上传版面）地点与备注”的顺序纵向排列，卡间距为 `10px`。IP 卡共用现有 `62px` 最小高度、`radius-card` 和 `16px` 水平内边距；右侧由“主 IP 输入／主题输入”组成，斜杠固定占位，主 IP 使用约 `55%` 可用宽度、主题使用其余宽度，两个输入均为灰底黑字、单行省略。主 IP 必填，主题选填。
- 识别结果底部主行动使用[数据校验](https://vibe-hub.org/data-validation)门禁：辅助抽赏要求 IP 非空、单抽价格有效且全部票数字段完整守恒；直接上传再要求地点与备注非空。任一总票数或已贴票数为空时，两条路径的按钮都必须立即回到禁用态；已贴票数为 `0` 不触发禁用。缺少条件时按钮使用 `#dfe2e7` 灰底、`#9a9da6` 文字、无阴影且不渲染光晕；满足条件后恢复既有黑底白字、阴影与玫红／紫色光晕。禁用态必须同时设置原生 `disabled`，不能只改变颜色。
- 低置信识别只保留为内部数据，不在奖级卡上增加“请核对”字样、紫色描边或其他异常编辑强调。单抽价格字段与“总票数”字段统一使用灰底黑字。
- 目标奖的选中与未选中卡片必须保持相同背景、边框和阴影；唯一视觉差异是左侧圆形选项是否显示黑底白勾。一番赏工作台的目标奖赏票同样不得附加紫色描边。
- 赏票撕拉采用用户指定的 React Spring 纸张教程结构，不使用 WXS 或 3D Page Curl：`.ticket-peel-swiper` 是向右移动且 `overflow: hidden` 的内部裁切窗口，`.ticket-peel-front` 以等量负向 `left` 保持前纸在票面原位并被窗口逐步裁掉，`.ticket-peel-back` 从撕裂边开始随位移增宽，以略浅黑色和 `4px 5px 15px -2px rgba(0,0,0,.4)` 投影表达纸背。外层 `.ticket-peel-track` 同样使用 `overflow: hidden` 把离场限制在当前赏票范围；不提升活动票卡层级，纸背不得覆盖相邻奖票。抽取提交不触发额外触觉反馈，也不得让页面整体震动。
- 奖票区使用双列紧凑网格。大赏与中／小赏在分组语义上保持分离，但卡片宽度遵循同一两列轨道；所有赏级的前纸统一沿用原始黑色（`#0a0a0a`），A/B/C 与 D/E/F 的奖级字母都使用普通白色字体，不添加渐变、彩金、辉光或字母动画。`NORMAL PRIZES` 的状态球容器至少保留三行：单球 `12px`、行间距 `4px`，三行内容最小高度为 `44px`；连同上下各 `6px` 内边距，普通赏底栏最小高度为 `56px`。不足三行的部分只由 `min-height` 留白，不创建青色占位球，也不改变真实票位数组。水平手势以 `96px` 为基础揭开行程，按当前向右速度最多投影到两倍距离；回滑按当前相对起点距离连续缩小纸背并重新覆盖。松手时投影进度不超过 `50%` 则使用 `320ms` 阻尼弹簧回到 `0%` 且不抽取，超过 `50%` 则弹簧甩至 `145%`，保证整张前纸退出内部裁切窗口；弹簧沿用教程默认 React Spring 的 `tension 170 / friction 26`。完整露出 `OPENED` 后提交一抽并显示轻提醒，纸背立即用 `80ms` 线性透明度淡出并复位。跟手阶段没有 transition，回弹／甩出由 TypeScript 纯函数生成约 `16ms` 一帧的位置序列。

### 6.5 页面互斥与状态恢复

- 任意时刻 `#pages-container` 中只允许一个 `.page-view` 可见；所有带 `hidden` 的流程页必须强制 `display: none`，页面族的 `display: flex/grid` 规则不得覆盖它。
- iframe 页面壳在内部路由切换时保持同一实例，父页面只同步地址栏，不得因为 `view` 变化重新挂载 iframe；这样避免导入页闪现和运行状态丢失。
- 从地图或“我的”返回识别时，恢复最近一个稳定识别页面和该页面的滚动位置；在识别标签内重复点击不产生跳转。相机和加载页属于临时状态，离开后回到导入页。
- 页面跳转前关闭所有临时模态；阻塞模态打开期间，底部导航与背景控件不可点击。

### 6.4 相机全屏布局

- 顶部安全区保持灰白页面背景；黑色相机取景区从 `top safe area` 下方开始并占据上方工作区，控制台固定在其下方，导航始终位于统一的底部锚点。
- 构图角标相对黑色取景区四角定位；四角与黑色区域的左右内距均为 `20px`，上下内距也保持对称，不使用会随页面尺寸漂移的固定像素坐标。小程序原生相机内的四角各使用一个直属 `48×48px cover-image`，弧线由对应方向的 `96×96px` 透明 PNG 固化并以 2 倍像素密度显示；禁止依赖原生相机覆盖层对 SVG 的解码，也禁止用方向性边框和多值圆角拼出角标。
- 识别首页“抽赏草稿”、“我的记录”与“我上传的版面”共用同一三行 `draft-card`，不得为“我的记录”另造字体、边框或高度。第一行左侧仅为 `抽赏记录 · A1B2C3` 或 `版面记录 · A1B2C3`，右侧状态只使用 `待上传／待核对／已上传`；第二行显示 `IP: … · M/D HH:mm`，有主题时显示 `IP: 主 IP / 主题 · 时间`；第三行从 `余 N / T` 开始，抽赏记录再追加 `已抽 N`。本机未提交记录为“待上传”，提交版面或赏票证据后为“待核对”，核对完成为“已上传”。编码固定为六位大写字母数字并保持完整。
- 工作台状态栏左半区在 `REMAINING` 上方增加 `IP:: …`；字号、颜色和字重与右半区“单价”一致，即 `9px / #a1a1aa / 700`。状态栏保持原 `92px` 外部高度，通过收紧内部上下内边距容纳新增行，不挤压余票数字或改变右半区基线。
- 提示胶囊位于取景区底部、快门上方，固定 `252px` 宽、最小 `52px` 高；左侧扫描图标为 `16px`，右侧两行文字固定为“将所需版面放在正中间／并尽量铺满取景框”，行高 `16px`。整组在胶囊内垂直居中，文字左对齐；不得缩成难读的单行或遮挡四个构图角标。
- 版面相机控制行固定为左右 `52px` 与中央 `72px` 三列：未拍摄时左侧为返回、中央为黑色快门加粉紫柔光、右侧保留 `52px` 空位；第一次快门只冻结按取景框中心 `aspect-fill` 裁切后的所见照片，快门中心出现 `28px` 白色对勾，右侧空位切换为灰底撤回图标；第二次点击对勾才检查每日额度并提交识别。V1 不显示相册图标或相册入口。
- 控制台的灰白渐层从取景区向下过渡；左右辅助按钮为无内阴影的灰色圆形，快门保留主行动的粉紫外缘反馈。
- 共享取证的“拍摄赏票”页沿用灰色全页背景，隐藏重复的顶部标题栏；返回箭头固定在顶部安全区，取景框从箭头下缘再留出 `12px` 间距。进入该页即在取景框内挂载原生相机，实时预览和拍摄结果都必须填满取景框，并由取景框的 `32px` 圆角裁切。
- 取景框、拍摄操作、地点与备注按纵向堆叠顺序排列；主胶囊位于取景框正下方并保持页面水平居中，宽度为 `212px`、高度为 `52px`，文字在内部双轴居中。右侧常驻 `52px` 圆形“撤回”按钮以 `12px` 间距锚定在主胶囊右侧，但不参与主胶囊的居中计算；地点与备注及确认勾选位于其后。
- 拍摄操作行的“拍摄赏票／已拍摄”主胶囊固定使用 `#0f0f10` 黑底与白字，不显示玫红／紫色光晕或内阴影；右侧“撤回”保持灰色圆形次操作。完成拍摄后主按钮文字变为“已拍摄”；撤回清除拍摄状态但不从布局中消失。
- 地点与备注右侧的确认勾选采用条件启用：必须同时满足“赏票已拍摄”和“文本框去除首尾空格后非空”。任一条件不满足时使用灰色禁用态且原生 `disabled` 阻断点击；两项满足时变为黑底白图标，并使用玫红／紫色双侧辉光。点击“撤回”会清除拍摄完成状态并立即恢复禁用态。
- 异常状态页与存储异常模态统一使用 `80px` 黑色圆形底板、`36px` 白色描线语义图标和 6.1 的异常状态卡片内部垂直节奏；图标含义必须按具体状态保留，不得再次统一成同一个信息 `i`。

## 7. 校验清单

每个页面在 390×844、375×697 与常见桌面宽度检查：

1. 首个可见元素未越过顶部安全区；普通固定页没有不必要滚动。
2. 同一页面族的标题／说明／行动组顺序和间距符合本规范。
3. 说明文本宽度、主按钮宽度和卡片宽度按各自 token，而不是互相偶然相等。
4. 底部导航在切换任意页面后保持同一视觉位置。
5. 文本缩放或窄屏下没有横向溢出、图标遮挡标题或主操作落入导航下方。
6. 路由切换前后始终只有一个页面可见，iframe 实例未重载，返回识别时页面和滚动位置均保持。

## 8. 维护

- 新增页面先归入一个页面族；无法归类时先增加一个有命名、有理由的变体，再写 CSS。
- 改动某个 token 时，必须复查该 token 覆盖的全部页面，而不是只截图单页。
- 本文件是 V1-29 的视觉参数来源；具体注入实现位于 `apps/web/app/api/v1-29-source/route.ts`。小程序必须把这些参数及其覆盖的完整页面效果一比一照搬到 WXSS；同名语义映射只用于平台语法适配，不得重新解释、简化或改写设计。
