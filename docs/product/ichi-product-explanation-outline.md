## 第一章：场景介绍——为什么需要这个程序

1. 一番赏与版面是什么：用图解释 IP／主题、赏级、剩余票、单抽价格与 Last。
2. 到店后的问题：清点、理解概率、跟踪逐抽变化、累计花费、误记恢复与暂停继续。
3. 出发前的问题：信息分散，地点与时间不清，照片中的状态可能已变化。
4. ICHI 的解决路径：地图发现 → 到店核对 → 拍摄识别与校正 → 辅助抽赏／仅上传 → 核验与合格共享 → 新的地图发现。

## 第二章：整体功能介绍——沿真实使用流程展示

1. 首页与两个入口：辅助抽赏、仅上传版面、本机草稿恢复。
2. 拍摄、识别与校正：取景确认、识别过程、可编辑结果、未知字段、价格与大赏标记。
3. 辅助抽赏工作台：余票与各赏概率、票面操作、一抽一记、累计花费、抽取历史、撤销、局面可能性、情境提醒与收手。
4. 上传与核验：两条上传路径、后台核验、待上传／待核对／已上传、对应的失败恢复。
5. 好版地图：搜索筛选、单点聚合、重叠选择、详情、来源时间、定位刷新。
6. 我的与记录管理：本机记录、本人已上传记录、恢复删除、可选资料与分享入口。

配图：优先使用已有宣传图，按操作顺序组织，每组说明解决的问题、操作与结果。

## 第三章：识别方案迭代——从图片到可用版面事实

1. 任务难点：美术字与 IP、赏级边界、票区归属、覆盖遮挡、计数与不完整证据。
2. OCR 与多模态方案演进：早期 OCR／辅助 OCR 候选、整版多模态方案及取舍。
3. 模型选型：历史候选与当前冻结基线；视觉理解、成本、等待时间、可校正性和调用边界。
4. 提示词与 Schema 优化：观察任务、字段职责、结构约束、标签规范、校验，以及 null／0 区别。
5. 机制优化与当前 R2：H0、R1、R2 的实际演进；直接剩余票观察；模型、确定性解析、用户校正与业务计算的分工。
6. 工程可靠性：图片传输、临时照片、任务幂等、失败恢复、旧响应保护、配额与赏票核验。

写作主线：遇到的问题 → 改动 → 效果与局限。历史候选、实验和当前运行方案分别标明。

配图：迭代时间线、同一难例前后对照、关键字段示例、当前识别链路。

## 第四章：地图交互与机制——从多次观察到共享线索

1. 交互设计：地图为主的布局、紧凑标签、语义缩放聚合、重叠列表、详情、触摸边界与恢复控件。
2. 信息表达：来源、版面状态、余票大赏、价格备注、观察时间、首次上传时间与新鲜度。
3. V1／V2 桥接：原上传确认 → V1 核验完成 → 本人当前条例适用与公开准入 → 正式 V2 数据与投影 → Marker。
4. 版面区分与前进继承：观察记录和实体版面不同；位置产生候选；结构、时间和状态变化约束匹配。唯一候选继承、无候选新建、多候选保留歧义。
5. 轻量用户判别：可跳过的双卡比较；同一版面／不同版面／无法判断；作为版本绑定的补充证据，不覆盖硬冲突。
6. 来源、生命周期与隐私：玩家与网络来源；新观察、删除、到期、安全撤除；私人证据和公开字段；关联不合并原始观察、来源或权利。

现行桥接要点：原上传确认表达分享意愿；V1 上传独立于条例；本人当前条例覆盖本人此前及以后完成上传的记录；V2 准入后自动生成地图显示，不增加逐记录二次分享步骤。
