# 情境提醒

> 状态：V1-D 工作认知，待用户验收
>
> 更新时间：2026-08-10

## 1. 目的

情境提醒是主操作界面上的轻量提示系统。它读取用户已经确认的抽赏记录，判断用户此刻处于什么抽卡情境，再给出一句及时、可关闭、不阻塞操作的提示。

它的职责是帮助用户读懂当前过程和及时收手，不是预测下一抽、评价用户输赢，也不是推动用户继续消费。提示必须和版面状态、目标奖选择、抽数及累计花费保持一致；不设置或要求用户配置任何成本节点。

## 2. 数据来源

唯一业务输入是当前本机会话中的抽赏记录和版面快照：

| 字段 | 用途 |
| --- | --- |
| `tier` | 本次抽到的奖级，例如 A、B、G、I |
| `isTarget` | 本次奖级是否属于用户开始前勾选的目标奖 |
| `remaining` | 抽完本次后的剩余总票数 |
| `cumulativeCost` | 截至本轮的累计花费；只用于显示与记录，不触发成本节点提醒 |
| `roundIndex` | 当前会话中的抽数序号 |
| `timestamp` | 计算连续抽取和本轮记录顺序 |
| `status` | 已确认或已撤销；撤销记录不触发奖励提示 |
| `tierRemaining` | 目标奖是否已无余量、版面是否发生关键变化 |
| `tierTotalSlots` | 当前奖级的总票位；本地派生大赏、中赏与小赏标签 |

情境分析不读取市场价、商家信息、用户画像或外部内容，也不根据既有花费推断用户应该继续投入。

### 2.1 奖级数量标签

提醒系统复用版面算法已经确认的总票位，不向识别模型索要分类：A—F、SP1—SP4 与用户确认后的其他特殊赏级按 `totalSlots ≤ 5／6—9／≥ 10` 依次是大赏／中赏／小赏；A1／A2 等编号款式仍归入同一个 A 赏，G—Z 固定为小赏。三档分类互斥，不影响票池计算、概率、目标选择、版面布局或抽取记录。

## 3. 分析流程

```text
DrawRecord[] + BoardSnapshot + TargetSelection
        ↓
SituationAnalyzer（纯规则分析）
        ↓
ReminderCandidate（情境、文案、优先级）
        ↓
主界面浮层（可关闭、自动消失、不阻塞抽取）
```

每次一抽确认后重新分析一次。撤销只更新版面和历史，不重复触发已经出现过的奖励提示；用户主动打开抽取记录时不额外弹出提醒。

## 4. 情境与文案

优先级数字越小越高。命中同一轮多个情境时只展示优先级最高的一条。

| 优先级 | 情境 | 触发条件 | 示例提示 |
| --- | --- | --- | --- |
| 10 | 首抽命中目标 | 第 1 抽且 `isTarget=true` | 一发入魂！ |
| 20 | 多抽后命中目标 | `isTarget=true` 且此前至少有 1 抽 | 中！！！ |
| 30 | 非目标大赏意外 | `isTarget=false` 且本次为大赏 | 意外之喜！ |
| 35 | 连着出高赏 | 最近 2 抽均为大赏 | 连着出高赏 |
| 40 | 目标奖已达成 | 本次后所有已选目标均已命中 | 目标到手！ |
| 45 | 目标只差一项 | 只剩 1 个已选目标未命中 | 还差一项 |
| 50 | 连续小赏 | 最近连续抽到小赏 | 见下方四档文案 |
| 55 | 连续同级中赏 | 最近 3 抽奖级相同、非目标且为中赏 | 又是这个 |
| 60 | 多抽无目标变化 | 最近 5 抽无目标命中 | 要不要收手？ |
| 65 | 抽数达到节点 | 达到 10、20、30 抽等节点 | 已抽 20 抽。 |
| 70 | 票池接近清空 | 余票低于初始票的 10% | 票池快见底。 |
| 72 | 小赏占比偏高 | 小赏占近 80% 且无目标命中 | 好多小挂件... |
| 75 | 目标奖已无余量 | 某个已选目标余量变为 0 | 这档没票了。 |
| 78 | Last 条件成形 | Last 规则确认且余票满足包套 | Last 条件已齐！ |
| 80 | 首次抽到新等级 | 本次首次出现此前未抽过的奖级 | 新等级登场！ |
| 82 | 连续抽取过快 | 短时间内连续确认多轮 | 先歇一下吧。 |
| 88 | 本次撤销完成 | 用户点击撤销且动作成功 | 已撤销 |
| 90 | 重复记录风险 | 同一轮疑似重复提交 | 这轮已记过。 |
| 95 | 数据不足 | 记录不足或状态冲突 | 先记下这一抽。 |

“G 赏、I 赏”等只是示例。正式规则只以本地已核对的总票位和用户目标选择为输入，不把某个字母永久定义为小赏。

连续小赏按连续次数选择文案，优先级保持为 50：

| 连续次数 | 示例提示 |
| --- | --- |
| 第 1 次 | 经典又时尚 |
| 第 2 次 | 又是经典时尚 |
| 第 3 次 | 又又又是经典时尚 |
| 第 4 次及以上 | 还是经典时尚|

## 5. 提示策略

- 奖励类提示只在真实命中或明确的意外大赏后出现，不把中赏或小赏结果包装成大奖。
- 防沉迷类提示使用疑问、提醒和收手选项，不羞辱用户，不暗示“差一点就会中”。
- 连续小赏文案只描述本次已发生的数量标签，不附带继续抽取、追加成本或翻盘暗示。
- “收手”按钮在主版面始终可见；用户触发停止意愿后，不再出现继续抽取的推动文案。
- 每次新抽取都重新展示本次最高优先级的情境提醒；不使用跨抽取冷却或同文案去重。连续小赏第 4 次及以后虽共用同一句文案，也必须每次显示。
- 提示按优先级去重，奖励提示优先于连续低关注奖，目标已达成优先于抽数节点。
- 提示只描述已发生事实，不给出中奖预测、概率保证或消费建议。
- 示例提示默认不超过 10 个汉字（数字、奖级和金额按界面需要另计），完整解释放在记录详情，不塞进浮层。

## 6. UI 行为

- 浮层位于主版面上方或不遮挡奖级票位的位置，使用 `role="status"` 和可读文本。
- 浮层左侧吉祥物按本轮奖级的本地分类切换表情：大赏使用四芒星眼睛，中赏保留现有圆点眼睛，小赏使用眯眼表情；图片只作装饰，奖级与提醒仍由可读文本表达。
- 默认短暂显示，自动消失；提供明确的关闭按钮。
- 不跳转新页面，不强制用户点击确认，不用声音、震动、全屏庆祝或倒计时制造压力。
- 低保真阶段先用本地 React 规则和固定案例演示；正式实现再抽成平台无关的纯函数模块，供网页主界面复用。

## 7. 禁止文案

以下表达不能出现在任何情境提醒中：

- “再来一次一定中”
- “都抽这么多了，不能停”
- “只差一点点”
- “不抽就亏了”
- “回本”“稳赚”“保底来了”

## 8. 验收案例

1. 第 1 抽命中用户勾选的 A 赏，显示“一发入魂”，不同时显示小赏或抽数节点提示。
2. 第 4 抽命中未勾选的 B 赏，且 B 的总票位不超过 5，显示“意外之喜”，不把它改写成目标命中；再次触发同一情境时仍显示新的本轮提醒。
3. 连续抽到总票位均为 10 张的赏时，前四次提示依次为“经典又时尚”“又是经典时尚”“又又又是经典时尚”“还是经典时尚”；第 5 次及以后每一抽仍显示“还是经典时尚”。
4. 连续 5 抽没有目标变化，显示收手提醒；点击“收手”后不再出现继续投入文案。
5. 累计花费增加只更新版面记录，不出现成本节点或要求用户预设金额。
6. 用户撤销上一抽，只显示“已撤销”，不生成新的奖励或防沉迷判断。
7. 抽赏记录存在冲突或数量不足时，不猜测情境，只显示数据不足提示。
