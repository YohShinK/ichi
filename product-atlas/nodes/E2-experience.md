## 主流程

```text
01 现场拍照／相册／手动录入
→ 02 生成结构化草稿
→ 03 逐项确认奖项、余票与单价
→ 04 运行票池一致性检查
→ 05 设置愿望、预算与停止条件
→ 06 比较概率、成本、Last 与替代购买
→ 07 选择抽／包／直接买／暂不参与
→ 08 保存私人快照与决策
```

## 关键状态

| 状态 | 系统含义 | 用户可执行动作 |
|---|---|---|
| `EMPTY` | 尚无票池 | 拍照、导入或手动创建 |
| `DRAFT_UNVERIFIED` | AI 或用户刚生成草稿 | 查看来源、逐项确认 |
| `NEEDS_CONFIRMATION` | 存在低置信度或缺失字段 | 修正、补拍或切换手动 |
| `INCONSISTENT` | 余票、奖项或批次信息矛盾 | 修正输入、保存观察或停止 |
| `READY` | 核心输入完整且守恒 | 设置愿望并运行计算 |
| `DECIDED` | 用户已选择四种结果之一 | 保存、复盘或结束 |

## 必须出现的确认点

- AI 识别后：每个字段可追溯到图片区域和置信度。
- 正式计算前：用户确认剩余数、奖项数量和单价。
- 强推荐前：预算、愿望和停止条件完整。
- 分享或导出前：再次检查地点、人物、订单号和票面编号。

## 异常与降级

| 异常 | 降级行为 |
|---|---|
| 图片无法识别 | 保留图片，进入完全手动录入 |
| 低置信字段 | 高亮并阻止一键跳过确认 |
| 输入不守恒 | 不显示“已验证”结果，只列出矛盾项 |
| 图片或现场信息过旧 | 标记信息不足，不给强结论 |
| 超出预算 | Last 和抽数建议只能为“不建议”或“无法判断” |
| 无网络 | 手动录入、计算、愿望和自检继续可用 |

## 体验原则

- 用户始终知道当前结果基于哪些输入。
- “暂不参与”和“无法判断”都是完整终点。
- 结果先解释组成项，再给推荐标签。
- 产品不使用“快抽”“回本”“再来一次”等刺激性语言。

## 最大待验证点

确认流程应该多短、多自动，才能既避免错误又不让用户在现场放弃。
