## 当前判断

ICHI 首先服务的不是“研究一番赏的人”，而是站在一次具体购买决定前、只有几分钟核对信息的用户。

> `APPROVED DECISION` 产品的最小场景是：用户在付款前看到一个仍在售的票池，希望得到特定奖品，却不知道应该抽几次、包套、直接购买还是离开。

## 问题现场

| 场景字段 | 0.1 草案 |
|---|---|
| Person | 有明确目标奖、预算有限，或正在考虑追 Last One 的一番赏用户 |
| Place | 线下门店、快闪店或线上售卖页面；信息由奖项板、进度表、聊天图片等分散呈现 |
| Time | 付款前的几分钟；票池可能继续变化，存在时间压力 |
| Trigger | 用户看见想要的奖品、剩余票数或 Last One，产生“现在值不值得参与”的念头 |
| Known | 单抽价格、肉眼可见的奖项、部分剩余信息、自己的愿望和预算 |
| Unknown | 录入是否完整、奖项与余票是否守恒、抽几次的真实概率、直接购买是否更合理 |
| Current Action | 手数进度表、询问店员、搜索计算器、参考二手价或凭感觉决定 |
| Decision | 抽指定次数、包套、直接购买、暂不参与 |
| Consequence | 超预算、错过目标、为 Last 付出过高成本，或因信息不足留下不信任感 |

## 现场分镜

```text
看到目标奖
→ 查看奖项板与余票
→ 无法快速确认信息是否能对上
→ 在时间压力下凭感觉比较抽／包／买／走
→ 付款后才知道是否偏离预算与愿望
```

## 证据状态

- `REPORTED` 多个公开讨论围绕余票不一致、Last One、包套和直接购买展开。
- `CALCULATED` 当剩余票数和目标数量成立时，概率与成本可以由确定性规则计算。
- `ASSUMED` 用户愿意在付款前投入少量时间拍照、确认字段并设置预算。
- `UNKNOWN` 现场可接受的拍摄张数、确认时长和最低信息量尚未经过真实用户观察。

## 当前最大未知

用户是否愿意为了更可靠的决定完成一次结构化确认，而不是继续依赖直觉。

## 0.1 场景裁决

1. 线下付款前是首发主场景；线上页面截图作为同一输入流程的兼容入口。
2. “追目标奖”和“追 Last One”共享同一主流程，只在愿望设置与结果解释中分支，不拆成两个产品场景。
3. 不预设确认时间上限；由 O2 的原型测试记录完成时长、放弃点和修正次数，再决定流程阈值。
