# V1 CloudBase 后端需求

> 状态：已批准实施
>
> 范围：V1-F 私有账号、微信身份映射、公开 ICHI ID、每日识别配额、结构化版面观察、六位记录码、删除、审计与仓库先行部署

## 1. 目标

ICHI V1 需要一个以 CloudBase 为运行平台的私有后端，用于：

- 识别当前微信用户并建立稳定账号；
- 隔离每个用户的私有数据；
- 执行每日版面识别配额；
- 调用固定版本的千问多模态模型；
- 保存用户确认后的结构化版面信息；
- 在辅助抽赏结束后，根据抽中赏票计算新的版面余票状态；
- 为 V2 好版地图积累带地点、时间、来源和质量状态的结构化观察记录；
- 支持本人查询、删除、后台维护与完整审计。

所有数据库结构、云函数、权限、索引、配置与部署清单必须先在仓库中完成并通过验证，再统一部署到 CloudBase。不得直接在控制台临时编写业务逻辑。

## 2. 已确认的数据边界

### 2.1 不持久化照片

- 版面照片和抽赏后的赏票照片只作为单次模型识别输入。
- 图片只能短暂存在于小程序本地临时文件、私有 `recognition-temp/` 传输对象、千问短时读取和云函数控制链中；同步云函数事件只传与任务绑定的 `fileID`。
- 图片不得写入 CloudBase 数据库、函数日志、审计日志、备份、长期任务数据或持久对象引用。正常链路结束立即双端删除，异常遗留最迟由 `1` 小时生命周期清理。
- 完成、失败、取消或超时后，不保留可重新下载的图片对象。
- V1 和未来 V2 地图均不依赖照片展示；地图标点只展示结构化文字、数值和由结构化数据生成的图表。

### 2.2 保存的两类信息

1. **初始版面信息**：模型从用户拍摄的目标版面提取、再由用户校正和确认的结构化快照。
2. **抽赏后更新信息**：辅助抽赏结束后，模型从赏票照片提取并由用户确认的抽中赏票事实，以及后端据此计算出的新版面快照。

直接上传版面路径只产生初始版面快照。辅助抽赏路径产生初始版面快照、抽赏事实和最终版面快照。

## 3. V1-F 范围

### 3.1 包含

- CloudBase 可信上下文中的微信原生身份。
- 内部私有账号与微信身份映射。
- “我的”页面展示的短公开 ICHI ID。
- 创始人和管理员可分配的保留短号。
- 北京时间每日 5 次版面识别配额。
- 识别任务、结构化模型结果、用户修订、版面观察、抽赏更新、六位记录码、删除任务与审计事件。
- 两条入口路径都记录用户授权后的位置快照。
- 面向人的后端说明、机器可执行契约、云函数、索引、权限和部署清单。
- 全部本地验证通过并经用户确认后，再进行一次受控的 CloudBase 批量部署。

### 3.2 不包含

- V2 公共地图集合、公开快照、匿名查询或发布接口。
- 自动将两个现实版面合并成公共地图点位。
- 露娜/Codex 自动审核发布。
- 社交资料、帖子、评论、私信、关注或奖励结算。
- 使用 ICHI ID、六位记录码、昵称、头像或客户端传入的 `accountId` 进行鉴权。
- 任何照片的云端长期保存。

## 4. 账号与标识符

### 4.1 内部 `accountId`

- 首次建号时由服务端生成不可枚举、不可变的随机内部 ID。
- 所有所有权、权限、配额、记录、删除与审计关系都使用内部 `accountId`。
- 内部 ID 不展示给用户，不发送给识别模型，不接受客户端用它声明所有权。

### 4.2 公开 `ICHI ID`

- 每个活动账号恰好有一个规范公开 ICHI ID。
- 普通账号使用 `ICHI-` 加 5 位随机无歧义字符，例如 `ICHI-7KQ2M`；排除 `I/O/0/1`。
- `ICHI-001` 至 `ICHI-999` 为管理员保留号，不参与普通随机分配。
- `ICHI-001` 固定预留给创始人。
- 公开 ICHI ID 只是显示和人工查找标识，不是访问密码。

可信关系为：

```text
微信可信身份 → 私有映射 → accountId → profile → 规范 ICHI ID
```

### 4.3 特殊号分配

- `founder` 和 `id_admin` 角色只能由服务端配置。
- 管理员可以通过目标当前的公开 ICHI ID，为已经注册的账号分配可用保留号。
- 更换公开号不改变内部账号、所有权、配额、记录、贡献或删除状态。
- 历史公开号不得分配给另一账号，可保留为指向原账号的非规范别名。
- 预留、分配、替换、拒绝和回滚都必须写审计事件。

## 5. 账号建立与“我的”页面

- 云函数从可信上下文读取 `APPID` 和 `OPENID`；忽略客户端传入的身份、角色、所有者和配额字段。
- 同一微信身份的并发首次请求只能建立一个账号。
- 账号、身份映射、资料、公开号登记和初始审计必须原子完成或可幂等恢复。
- 未建立云账号时，“我的”页面继续显示 `LOCAL-001` 和本机模式。
- 建号成功后显示服务端返回的规范 ICHI ID，绝不显示内部 `accountId` 或 OpenID。
- 首次登录必须发生在任何版面识别之前。
- 微信身份认证由小程序调用云函数时的可信上下文静默完成；点击头像不是登录鉴权本身，而是“建立／完善 ICHI 账号”的用户入口，用于取得昵称、头像等可选资料授权。
- 用户首次使用且资料未完成时进入“使用微信登录”引导，明确授权微信头像和昵称；完成后不重复引导。用户可从“我的”页头像或用户名再次授权并更新展示资料，但资料变化不能改变内部账号、ICHI ID、记录归属或配额。
- 昵称、头像、公开 ICHI ID 均不得参与身份判断或数据所有权判断。

## 6. 版面识别与配额

- 每个标准账号每天最多提交 5 次版面识别，以北京时间自然日计算。
- “进入辅助抽赏”和“仅上传版面”共享这 5 次配额。
- 每次模型调用必须经过 `reserve → commit` 或 `reserve → release` 状态机。
- 权限拒绝、主动取消、网络/供应商失败、超时、无效模型输出，以及未获得有效结果前退出，不消耗已提交次数。
- 同一幂等键最多触发一次模型调用和一次配额提交。
- 抽赏后的赏票识别属于同一辅助抽赏会话的更新步骤，不额外扣除一次“版面识别”配额，但仍记录模型成本。
- 系统需要全局日调用量/成本熔断；熔断不影响本地草稿和手动核对。
- 后端提供独立的本人配额状态查询，至少返回 `limit`、`used`、`reserved`、`remaining`、`dateKey` 和 `resetAt`；前端进度环只展示该服务端事实，不在本地自行计算权威余量。
- 配额耗尽使用稳定错误码 `QUOTA_EXHAUSTED`；`reserve-recognition` 仍是唯一有权预占名额的入口，配额查询结果不能代替预占。

## 7. 初始版面结构化快照

模型输出只是待核对草稿，必须由用户确认后才能保存。至少包含：

- 目标版面边界选择结果；
- 规范中文主 IP、可选主题、候选、置信度和识别依据；
- 单抽价格、总票数、已贴/剩余票数；
- 奖级、奖品名称、每级总票位、已贴票位和剩余票位；
- Last/最终赏等特殊机制；
- `SP1` 至 `SP4` 独立特殊赏；
- 无法归类或低置信字段及问题码；
- 用户修订后的最终字段。

归一化规则：

- `A1/A2`、`B1/B2`、`C1/C2` 等同级分层归并到所属基础奖级 `A/B/C`；所有基础奖级都适用。
- `SP1`、`SP2`、`SP3`、`SP4` 保持为四个独立特殊赏级，不合并为一个 SP。
- 超出契约的特殊赏或无法确定归属时使用 `UNKNOWN/OTHER`，必须人工修正后才能最终确认。
- 识别多版面照片时，先分割候选版面，选择“最接近画面中心且占画面面积最大”的单一目标；无法唯一确定时要求用户重拍或选择，不静默混合多个版面。
- 主 IP 与主题必须分开返回；常见外文别名（例如 Persona、Arknights）由服务端规范为中文主 IP，周年、联名、章节或子系列保留为可选主题，主题为空不阻止用户确认。
- 实体票容量和已贴票数是独立证据；空的空位坐标数组不证明“没有空位”，实体票数量也不得自动把已贴数补成总数。只有逐排证据明确 `open=0` 且 `unknown=0` 时才可判定该赏全部已贴。

## 8. 抽赏后更新与确定性计算

辅助抽赏结束后保存：

- 小程序本次会话的抽取历史；
- 赏票照片提取出的奖级与张数；
- 用户对赏票识别结果的修订；
- 两者的差异与最终确认结果；
- 后端计算出的最终版面快照。

基础计算规则：

```text
最终剩余[奖级] = 初始剩余[奖级] - 已确认抽中数量[奖级]
最终总余票 = 初始总余票 - 已确认抽中总数
```

服务端必须阻止：

- 抽中未知奖级；
- 任一奖级结果为负数；
- 抽中数量超过初始余票；
- 分级数量与总数不守恒；
- 小程序抽取历史与赏票识别事实不一致却被静默覆盖。

发生不一致时记录 `needs_user_confirmation`，由用户选择或修正后再生成最终快照。计算过程保存版本号，未来可以重放结构化数据，但不依赖原照片。

同一版面允许用户留在工作台继续抽取并再次提交赏票。每次提交都使用同一 `recordId/boardId` 和严格递增的 `submissionVersion`，携带截至当时的完整累计抽取计数；同版本重试幂等，旧版本的迟到结果标记为 `superseded`，不得覆盖较新的核对结果或最终快照。

## 9. 地点、时间与未来地图

- 两条拍摄路径在识别前都必须申请位置授权。
- V1 版面输入只允许页内实时相机，不提供相册照片；第一次快门冻结与取景框中心裁切一致的照片，第二次对勾确认才执行配额检查并提交识别，撤回可恢复实时取景。
- 每条观察保存位置坐标、位置精度、授权版本、观察时间和服务端接收时间。
- V1 只保存私有结构化观察候选，不写入公共地图。
- V2 发布时，地图点展示结构化版面状态，并明确显示“几天前”或具体日期时间，不能宣称是实时库存。
- V1 历史数据可作为 V2 候选数据；是否公开、同地点合并和新旧覆盖必须经过 V2 独立治理门禁。

## 10. 六位记录码

- 每次新的版面拍摄由服务端分配一个新的 6 位数字与字母组合记录码。
- 两个人拍摄同一现实版面时仍各自获得不同记录码；记录码标识一次观察，不标识现实版面本体。
- 六位码用于人工查找、客服沟通和溯源，不用于鉴权、所有权证明、去重或访问私有记录。
- 码值由注册表保证唯一；旧码和兼容别名不得重新分配。

## 11. 私有数据与结构化溯源

由于不保存照片，每条记录必须保留足够的结构化溯源：

- 模型原始结构化输出；
- 用户确认后的结构化输出；
- 字段级修订差异；
- 模型、提示词、JSON Schema、归一化规则和推导算法版本；
- 识别任务 ID、幂等键、来源路径和六位记录码；
- 置信度、问题码、守恒检查结果和状态迁移；
- 位置快照、观察时间、服务端时间和授权/披露版本；
- 抽取历史、赏票识别事实、用户选择和最终推导结果。

结构化溯源可以支持审计和重算，但不能等价替代照片复核。发生无法从结构化信息解释的争议时，记录只能降级、拒绝进入 V2 或要求重新拍摄，不能伪造确定结论。

## 12. 私有权限与防伪造

- 所有业务集合默认禁止客户端直接写入。
- 小程序通过云函数执行跨集合、模型、配额和维护操作。
- 服务端从可信微信上下文推导所有者。
- 客户端传入的 OpenID、`accountId`、owner、角色、配额、记录码、审核状态、公开资格和删除完成状态不得作为权限依据。
- 模型结果不能直接写入最终观察、配额、角色、审计或未来公共集合。
- ICHI ID 和六位码不能读取私有位置、模型草稿、抽赏事实或本人记录。
- V1 不创建公开可读的业务集合或存储目录。

## 13. 删除与保留

- 用户可以查询和删除本人的私有观察记录。
- 记录删除在 24 小时内完成；账号删除先停用访问，再在 7 天内完成关联私有数据清理。
- 删除任务必须可重试，并记录最小必要审计结果。
- 照片不形成持久资产，但必须存在正常链路即时删除、客户端补删和 `recognition-temp/` 的 COS 最短 `1` 天过期删除兜底；不存在 180 天图片保留任务，且不把按日异步生命周期误述为精确 24 小时删除。
- 模型原始结构化输出、用户修订和推导快照的具体保留期限在上线前由隐私文案和删除政策统一确认。

## 14. 仓库先行与部署门禁

1. 确认本需求。
2. 在仓库内完成技术设计、数据契约、函数边界、权限和部署清单。
3. 完成云函数、共享库、索引/权限配置与后端自动测试。
4. 形成一份面向人的云端说明和一份可部署的代码端产物。
5. 通过类型检查、单元/集成测试、Schema 校验、安全审查、CloudBase 代码审查和部署 dry-run。
6. 向用户提交精确的 CloudBase 变更清单并获得确认。
7. 先在 CloudBase 开发环境一次性创建集合、索引和权限，部署函数/定时触发器，配置非秘密环境值，并独立验证后端接口。
8. 后端开发环境通过后，再接入小程序首次微信登录引导、可再次授权更新的头像／昵称、动态 ICHI ID、左上角配额分数环、耗尽弹窗和其余业务接口。
9. 用户在 CloudBase 密钥管理中配置千问 API 密钥；密钥不进入仓库、客户端包或日志。
10. 在正式小程序 AppID 与目标环境上完成真实账号、位置、相机、识别、配额、删除和恢复验证。

## 15. 验收标准

- 同一微信身份重复或并发建号只得到一个内部账号与一个规范 ICHI ID。
- 创始人可安全取得 `ICHI-001`，管理员可审计地给已注册朋友分配保留号。
- 客户端无法伪造身份、所有者、角色、配额或公开资格。
- 两条入口共享每天 5 次版面识别；失败、重试和幂等行为不会重复扣费。
- 两条入口都在识别前取得并记录位置授权。
- 任何成功或失败链路都不会在 CloudBase 中留下照片文件或图片字段。
- 直接上传保存初始结构化快照；辅助抽赏保存初始快照、确认抽赏事实和确定性最终快照。
- A1/A2 等归并到基础奖级，SP1—SP4 保持独立；守恒错误和冲突不能静默通过。
- 用户只能查询和删除本人记录；删除任务可恢复、可审计。
- V1 云端不存在公共地图写入、公共快照或公开发布接口。
- 所有云端资源都能由仓库清单复现，CloudBase 控制台不是唯一事实源。
